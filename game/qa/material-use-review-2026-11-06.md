# 수확한 재료의 쓰임과 자연도감 후속 검토 · 2026-11-06

이번 범위는 생활 경험의 앞선 다섯 완주를 반복하지 않고, 남아 있던 작물·꽃잎·사과·생선의 수량과 결과 연결을 대조했다. 실제 작물 패널 검증, 생산 코드의 상태 모형 검증, 자연도감의 컴포넌트 배치 검증은 서로 구분한다.

## 사용자가 얻는 개선

- 작물 패널에 ‘수확한 작물은 어디에 쓸까요?’를 접어 두었다. 딸기·복숭아·배·귤은 각각 2개로 카페 2층의 해당 주스를 만든다는 실제 사용처를 알 수 있다. 토마토·호박·잎채소는 현재 요리나 장식에 쓰이지 않는다는 사실을 명확히 알린다. 쓰임 안내를 펼쳐도 주요 행동과 산책 복귀 버튼에 스크롤로 접근할 수 있다. 본문은 15px, 펼침 영역은 최소 48px이다.
- 자연도감에 ‘간직한 구이 접시’를 표시한다. 집에서 장식 접시로 만든 물고기와 캠핑장에서 구워 먹은 물고기를 구별하여, 발견 수보다 가방 수량이 적어진 이유를 설명한다. 아직 집에 놓지 않은 소유 접시도 포함하므로 ‘집에 놓은 접시’라는 표현은 쓰지 않았다.
- 저장 형식, 수확량, 소비 규칙은 바꾸지 않았다. 접시 수는 유효한 저장 자료에서 기존 소비 수와 식사 수의 차이로 계산한다.

## 실제 쓰임과 남은 제품 과제

| 재료 | 현재 연결 | 판단 |
| --- | --- | --- |
| 딸기·복숭아·배·귤 | 작물당 수확 2개 → 해당 주스 1잔. 카페에서 반복 소비 | 수확의 다음 행동이 존재하며 안내에서 연결 |
| 토마토·호박·잎채소 | 작물당 수확 2개 → 가방 수집 | 사용처를 정직하게 안내했지만, 반복해서 수확할 이유는 여전히 약함. 후속 소비 연결 필요 |
| 꽃잎 | 화단 세 곳 총 9개 → 꽃병 1개·화관 2개 소비 | 두 장식을 만든 뒤 6개가 남음. 장식 제작은 일회성이므로 반복 쓰임은 후속 과제 |
| 사과 | 집 장식 음료 쟁반 2개·잼 3개, 카페 사과주스 2개 | 장식과 반복 음료 소비 모두 존재 |
| 물고기 네 종류 | 집에서는 종류당 구이 접시 1개를 간직, 캠핑장에서는 반복 식사 | 두 결과 모두 가방에서 실제 소비하며 도감 발견 기록은 보존 |

집의 샐러드·팬케이크·코코아 요리는 별도의 계량 놀이이며 현재 채집 작물을 소비하지 않는다. 그 요리의 임시 계량 값을 작물 소비 장부로 해석하지 않았다.

## 검증 근거

### 실제 작물 패널

`scripts/material-use-ui-2026-11-06.mjs`의 최종 결과: `material-use-ui-2026-11-06/final/results.json`.

- 실제 지도에서 공원으로 이동한 뒤, 7종 각각의 근접 위치를 준비하고 실제 행동 버튼으로 패널을 열었다. 접힌 안내를 펼쳐 정확한 문구·15px 이상 본문·48px 이상 펼침 영역·가로 넘침 없음을 확인했다.
- 물 주기 또는 수확 버튼까지 스크롤로 접근한 후 산책 복귀를 실제로 눌렀다. 이번에는 수확이나 물 주기를 실행하지 않았고, 전후 작물 상태와 재료 가방이 같았다.
- 390×844에서 7종, 844×390·768×1024·1440×900에서 딸기 패널의 펼침과 복귀 버튼 접근을 확인했다. 폰 세로 토마토와 가로 딸기 캡처를 직접 열어 안내와 복귀 버튼의 배치를 검토했다. 패널을 스크롤하면 상단 제목이 화면에서 벗어나는 것은 정상적인 패널 스크롤이다.
- 최종 `health.json`의 페이지 오류·콘솔 오류·실패 요청은 모두 빈 배열이다. 브라우저는 종료했다.

### 수량 및 소비 모형

`material-use-ui-2026-11-06/model-ledger.json`은 실제 생산 reducer와 저장 검증기를 실행한 결과이다. 실제 기다리기나 브라우저 수확 완주를 의미하지 않는다.

- 7종 각각의 수확량 2개, 익은 뒤 계절이 바뀌어도 수확 가능, 제철이 아닌 새 물 주기 거절을 확인했다. 과일 네 종류는 실제 주스 제작으로 2개를 소비하며 남은 수량 0이다.
- 꽃밭은 서로 다른 활동으로 성장하고 같은 활동 중복은 성장에 더해지지 않는다. 세 화단의 꽃잎 9개, 장식 3개 소비, 나머지 6개, 동일 화단 중복 수확 거절을 확인했다.
- 사과 두 나무 수확·음료 쟁반 제작·재료 부족 거절·서로 다른 세 활동 뒤 다시 열림·잼 제작을 대조했다. 총 수확 6개에서 2개와 3개를 써 1개가 남고, 이미 가진 장식 중복 제작은 거절된다.
- `tests/nature-guide-ledger.test.mjs` **4/4 통과**. 네 어종 모두 실제 통합 reducer로 3마리 발견 → 집 접시 1개 → 캠핑 식사 1마리를 검증했다. 가방 1 + 접시 1 + 먹은 수 1 = 발견 3이며, 집 접시 중복 소비가 거절되고 첫 발견 정보가 유지된다.

### 자연도감 배치와 독립 검토

`material-use-ui-2026-11-06/final/nature-guide-component.json`과 `nature-guide-component-*.png`는 실제 자연도감 함수·CSS에 실제 생선 상태 모형의 결과를 넣은 **컴포넌트 배치 검사**다. 네 화면 크기에서 가방 1마리·식사 1마리·접시 1개가 표시되고 가로 넘침이 없음을 확인했다. 390×844 캡처를 직접 열어 네 수량 행과 발견 정보가 읽히는 것을 확인했다. 실제 낚시·집 요리·캠핑 생선 요리를 이번 브라우저에서 완주했다는 근거로 사용하지 않는다.

별도 검토 담당자가 과일 네 종류의 비용과 카페 활성 메뉴, 생선 저장 검증의 `소비 = 식사 + 소유 접시` 관계를 대조하고 4개 회귀를 재실행했다. 이번 변경의 차단 문제는 발견하지 않았다.

## 다음 주기의 최소 연결 제안

1. **우선 검토: 수확 장식 세 가지.** 기존 `GATHERING_RECIPES`와 세 단계 준비·집 배치 흐름을 재사용해 토마토·호박·잎채소 각각 2개를 작은 수확 장식 하나로 바꾼다. 사용자는 수확한 결과를 집에서 다시 볼 수 있다. 기존 일회성 재료 계산을 재사용할 수 있지만 새 장식 ID·표시 이름·실제 외형·레시피 진입이 필요하다. 현재 고정 등록부의 새 영구 소비이므로 작은 저장 형식 마이그레이션과 구버전 보호까지 포함해야 한다. 현재 출시 묶음에는 구현하지 않았다.
2. **반복 방문용 후속: 친구와 수확 접시 나누기.** 기존 카페 동행·식사 흐름에서 채소를 나눌 수 있도록 한다. 반복 수확의 이유는 더 강하지만 반복 소비 장부 또는 음식 종류 확장, 담기·먹기·외형·저장 검증까지 범위가 넓다. 별도 주기로 다루는 것이 적절하다.

수확 누적 기록을 지워 소비를 표현하거나, 기존 주스 수량·가상 샐러드 계량 값을 빌려 쓰는 우회는 피한다. 발견 기록 손실과 중복 소비를 막기 위해 실제 사용 결과와 저장 장부가 일치해야 한다. 이번 안내 개선만으로 채소 세 종류의 효용 문제가 해결됐다고 판정하지 않는다.

검증은 Chromium 에뮬레이션과 공유 소프트웨어 WebGL에서 이루어졌다. 실제 휴대폰·태블릿의 성능과 장기적인 반복 재미는 별도 검증 대상이다.
