# 생활 경험의 힐링·휴식·즐거움 검토 · 2026-11-06

이번 검토는 11월 1일의 대표 기능 통과를 그대로 재선언하지 않고, 당시 남겨 둔 사진첩 용량·삭제·단체사진, 마음별 편지, 카페 2층의 음료·동행·식사 흐름을 끝까지 조작했다. 실제 입력으로 얻은 결과와 컴포넌트 회귀, 시각 검토의 범위를 구분한다.

## 개선과 사용자가 얻는 변화

- **사진을 안전하게 간직하기.** 6장 제한에서 이유 없이 촬영 버튼만 잠기던 화면에 보관 방법과 ‘사진첩에서 자리 만들기’를 제공한다. 삭제하기 전 선택한 사진과 현재 걸린 벽을 보여 주며 ‘사진 남겨두기’에 먼저 초점을 둔다. 취소는 저장하지 않고, 사진 선택·새 액자 저장·벽 변경은 낡은 삭제 확인을 해제한다. 저장 실패 때 사진과 벽을 유지하고 확인 영역 안에 재시도 안내를 보여 준다.
- **전한 마음에 맞는 답장.** 세 친구에게 안부·감사·발견을 전하면 각각 다른 9편의 답장이 온다. 읽은 편지 목록에 마음 제목을 함께 보여 주고 새 답장을 바로 읽는 버튼을 둔다. 출석이나 보상 수집을 강요하지 않는 짧은 휴식 내용이다. 이미 저장된 답장은 읽음 표시 저장이 실패해도 읽을 수 있으며, unread 상태와 재시도 기회는 유지한다. 기존 편지 ID와 저장 형식, 케이크 1회 소비 규칙은 유지한다.
- **카페의 첫 행동이 보이는 시야.** 처음 입장했을 때 건물 두 층 전체를 맞추고 2층 바닥이 작업대를 가리던 연출을 1층 중심으로 바꿨다. 좁은 세로 화면은 도름이·첫 반죽 작업대·계단 입구가 함께 보이는 중앙 구도로 시작한다. 실제로 걸으면 가까운 기존 보행 시야로 이어진다. 위층은 계단을 올라갈 때, 또는 이용자가 전체 보기를 고를 때 드러난다. 수동 카메라 선택과 활동 카메라의 소유권을 존중한다.

카페 첫 구도는 별도 디자인 담당자가 이전·수정 캡처를 직접 대조했다. 첫 수정은 도름이가 커졌지만 빈 바닥과 문틀만 보여 반려했고, 1층 부분 구도와 세로 화면용 중앙 구도로 다시 다듬었다. 최종 390×844 정상 DPR1 화면에서는 도름이·반죽대·계단 첫칸이 함께 보여 시각 범위 합격으로 판정했다. 전체 놀이의 재미나 실물 휴대폰 성능을 이 판정으로 대신하지 않는다.

## 독립 코드 검토와 회귀

독립 검토자는 삭제 확인 중 새 액자를 만들면 이전 삭제 확인이 남아 버튼이 반응하지 않는 경우를 지적했다. 새 저장과 벽 변경 때 확인을 해제하고 다음 테스트에 포함했다. 읽음 표시 실패 때문에 답장을 못 읽던 기존 마찰도 함께 개선했다.

`node --test tests/cafe-readable-entry.test.mjs tests/living-memory-actions.test.mjs` **10/10 통과**.

- 사진 삭제 확인/취소·선택 변경·저장 실패 후 재시도·벽 변경·확인 중 새 액자 저장.
- 편지 보내기 실패 때 선물 보존, 읽음 저장 실패에도 내용 표시와 unread 보존, 재시도·중복 선물 방지, 기존 9개 ID의 다른 답장 해석.
- 카페 첫 방문의 1층 가시성, 계단/전체 보기/복귀, 일시정지, 첫 보행 구도 전환과 수동 카메라 보호.

사진·편지 회귀는 실제 reducer와 UI 모듈을 사용하지만 DOM과 사진 미리보기는 검사 전용 대역이다. 실제 3D 렌더링·다운로드·터치 검증을 대체하지 않는다.

## 실행 방식과 한계

사진·편지와 카페 완주에는 Chromium 터치 에뮬레이션을 사용했다. QA 브리지는 이동 목적지와 근접 위치를 준비하거나 현재 상태를 읽는 용도이며 성공·재료·타이머·점수를 주입하지 않았다. 카페 계단은 입구부터 실제 터치 스틱으로 걸었다. 사진관·우체국 등 방 사이 이동은 실제 지도 UI를 썼다. 첫 하네스 실패는 새로고침 뒤에도 사진관에 있다고 가정한 것과 카페의 이동 주체를 고려하지 않은 근접 setup 때문이었고, `mobile/`에 남긴 초기 실패와 `mobile-final/`의 새 세션 결과를 구별한다.

캠핑의 첫 실행은 지연 로딩 직후 runtime 할당을 기다리지 않은 하네스 오류로 중단되었다. 실제 ready 상태를 기다리도록 수정한 새 세션에서 굽기·먹기·재시도·퇴장을 완료했으며 제품 성공 상태를 주입하지 않았다.

긴 완주에서는 DPR 0.35와 12프레임마다 그리기를 사용하고 캡처 때 정상 그리기를 요청했다. 입력·시계·모형은 그대로다. 최종 카페 시각 캡처는 DPR1이다. 모든 실행은 공유 소프트웨어 WebGL이며 iPhone/iPad/Android 실물, Safari, 실제 스피커 청취, 열·배터리·장기 재방문 만족도를 측정하지 않았다. 사진 전체 친구/벽 조합, 모든 카페 손님/음료/재료 부족/동행 취소 조합까지 완주했다는 뜻은 아니다.
