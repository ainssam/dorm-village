## 방향과 검수 방식

[개선 계획](../docs/healing-quality-plan-2026-11-06.md)에 따라 첫 경험, 학습, 생활, 놀이·체육, 교통, 디자인, 저장·권리 조건을 나누고 서로의 변경을 검토했다. **힐링·휴식·즐거움과 놀다가 만나는 작은 배움**을 기준으로 삼았다. 편안한 관람도 하나의 완성된 경험으로 인정하며, 조작 놀이에는 읽을 수 있는 반응·결과·재시도를 요구한다. 출석·완료율을 의무로 만들거나 결제 기능을 추가하는 주기가 아니다.

이 문서에서 증거는 다음과 같이 구분한다.

| 증거 종류 | 확인할 수 있는 것 | 대신하지 않는 것 |
| --- | --- | --- |
| 실제 앱 UI | 제품 모듈을 불러온 브라우저에서 실제 버튼·폼·키보드·터치 입력으로 결과와 복귀 확인 | 실물 휴대폰·Safari 성능, 실제 이용자의 재미 |
| 모델·컨트롤러 회귀 | 실제 reducer/컨트롤러의 저장 보존, 수량, 실패·재시도, 생명주기 | 실제 3D 접촉·네이티브 터치·렌더링 |
| DOM·컴포넌트 | 실제 HTML/CSS/UI의 배치·접근·표시와 fixture의 표현 | 전체 게임 이동·활동 완료·실저장 |

| 정지 화면 | 해당 프레임의 구도·색·글자·가림 | 연속 애니메이션·장시간 이용의 품질 |

일부 실제 앱 검수는 장소 또는 충돌 없는 근접 위치만 준비했다. 완료·도장·재료·시간을 주입한 것은 아니다. 근접 위치에서 시작한 검사를 지도 입구부터 걸은 전체 경로로 표현하지 않는다. 긴 WebGL 실행의 낮은 DPR/그리기 샘플링과 정상 DPR1 시각 검토도 상세 보고서에서 구분한다.

## 공용 메뉴와 첫 사용

- 휴대폰에서 생활 메뉴를 시점 조작보다 먼저 배치했다. 확대·회전·기울기는 접고 펼칠 수 있으며, 메뉴를 다시 열면 주 메뉴부터 보인다. 카메라 도구의 펼침 선택은 유지한다.
- 지도 버튼의 전경색 누락을 고쳤다. 실제 DOM 측정 대비는 **1.14:1 → 7.87:1**이다.
- 첫 안내의 ‘호기심을 따라’는 소개한 활동을 선택하는 배움 안내로 연결한다. 쉬기/놀이/배움 필터마다 해당 추천이 남으며 검색 중에는 검색 결과를 보여 준다.
- 작은 하루는 실제 간직한 순간부터 보여 주고, 미발견 목록은 선택해서 펼친다. 빈 기록은 쉬어 갈 곳으로 이어 준다. 숙제 표현을 걷어 내고 로봇·균형 기록도 실제 여러 과제에 맞게 정리했다. 기존 발견 ID는 유지한다.

**DOM 검증:** `first-impression-dom-review.mjs`는 실제 `ui.js`, `hud.js`, CSS로 폰 세로/가로·태블릿 세로/가로·컴퓨터 **5/5**를 통과했다. 추천·검색·키보드 펼침/닫기·스크롤 복귀·기존 기록 표시를 확인했다. 게임 렌더러는 실행하지 않았고 기존 기록은 fixture다.

**실제 앱 검증:** `healing-shell-acceptance.mjs`는 **390×844, 844×390, 768×1024, 1024×768, 1440×900의 5/5**에서 첫 배움 안내→로봇방, 피아노 검색→음악실, 쉬기 추천→공원으로 실제 이동했다. 확대·방 맞춤·Escape 메뉴 복귀를 확인했고 예외/HTTP 오류는 0이다. 벤치 근처를 준비한 뒤 실제 행동으로 앉기→기록 발생→일어나기→기록 열기→전체 새로고침 후 보존도 새 세션에서 확인했다.

근거: `first-impression-dom-2026-11-06/results.json`, `healing-shell-2026-11-06/results.json`, `healing-shell-tablet-desktop-2026-11-06/results.json`, [첫 경험 독립 검토](first-impression-review-2026-11-06.md).

## 작품 보존과 미술 입력의 최종 확인 범위

독립 저장 감사에서 실제 손실 가능한 두 경로를 찾고 수정했다. 미술은 기존 초안을 읽기/해석하기 전에 그린 임시 작품이 보지 못한 저장 그림을 덮을 수 있었다. 수학은 첫 읽기 실패 후 만든 분필/입력식이 다음 읽기의 옛 저장본으로 바뀔 수 있었다. 수정 후 미술6개·수학5개의 표적 회귀가 통과했다. 저장 키/스키마를 바꾸거나 새 백업/계정을 만든 수정은 아니다. [저장·복구 상세](save-recovery-review-2026-11-06.md).

최종 실제 게임 근거는 `art-fullgame-paced-final-2026-11-06/results.json`과 `audit-health.json`이다. 정상 미술과 지연 복원 **2/2 통과**, 페이지/콘솔/실패 요청0이며 독립 검토자가 결과 JSON과 내보낸 PNG·로딩 화면을 직접 확인했다. 지연 검사는 실제 기존 작품 준비→read 지연 중 조기 획/파괴 입력 차단→기존 픽셀 정확 복원→새 획과 첫 저장6회→전체 재접속→실제 PNG까지 수행했다. 입력 조건은 **DPR1, 획10개 이동×20ms와 떼기 전20ms, tap 전600ms·누름80ms**다. 제품 입력 이벤트 코드는 이 결과를 얻기 위해 바꾸지 않았다.

앞선 첫 tap 누락은 한 CDP 세션·Three 없는 실제 DOM·여러 입력 조건에서 비교했고 최소 HTML에서도 첫 click0/12로 재현했다. [앱 없는 터치 대조](touch-input-control-2026-11-06.md)와 [압축 결과](touch-input-control-summary-2026-11-06.json)는 버튼만 tap12/12, 즉시 획 뒤 tap0/12, 시간 간격이 있는 획+tap 전600ms 조합12/12를 구분한다. 같은 최종 조합의 실제 미술 DOM도12/12였으며 전체 게임으로 이어 검증했다. 이는 저장 보호 코드만으로 설명할 수 없는 합성 제스처 현상을 분리하고 이 환경의 재현 가능한 성공 조건을 확인한 근거다. 특정 Chromium 버전/프로토콜 원인, 모든 빠른 입력, 실물 기기의 합격은 확정하지 않는다. 일부500ms 대기의 실패와 이전 원시 실패를 보존하며 최종 결과로 덮지 않는다.

초기 수학 undo의 즉시 PNG 비교, 잘못된 공간 뷰를 읽은 QA 훅, 간식 overview라는 이름의 walk 결과처럼 근거가 잘못된 사례는 교정 결과와 분리했다. 제품 수정이 없었던 QA 교정을 제품 버그 해결 건수로 세지 않는다.

## 다음 개선 후보

현재 출시 준비와 분리하여, 실제 쓰임이 약한 부분부터 후속 주기를 선택한다.

1. **채소 수확의 결과 연결.** 토마토·호박·잎채소는 현재 가방 수집 외 사용처가 약하다. 안내를 정직하게 고쳤지만 반복 수확 이유를 해결한 것은 아니다. 기존 제작/집 배치의 작은 수확 장식 또는 친구와 나누기 중 실제 결과가 보이는 최소 범위를 검토한다. 새 영구 소비가 필요하면 저장 장부·구버전 보존까지 별도 주기로 다룬다.
2. **한 번 만든 뒤 남는 재료.** 꽃잎 장식 제작 후 남는 재료와 일회성 결과의 반복 쓰임을 검토한다. 수확 기록을 지워 소비처럼 보이게 하거나 다른 요리의 임시 계량을 재료 장부로 오인하지 않는다.
3. **조작 놀이의 이해와 재도전.** 패스의 다섯 배치는 모델상 성공 가능하지만 이번 실제 UI는 1/5였다. 안내만 보고 이동·조준·받기와 실패 이유를 이해할 수 있는지 실제 이용 관찰을 우선한다. 자동 명중이나 보상 추가를 개선의 기본값으로 삼지 않는다.
4. **실물 기기와 처음 온 이용자.** 폰·태블릿의 첫 안내→하고 싶은 놀이→결과→보관/복귀를 직접 관찰해 터치·가독성·재방문 동기를 확인한다. 자동 회귀의 통과 수를 만족도나 교육 효과로 대신하지 않는다.

상용 제품 비교는 [기존 공식 자료 기반 비교](market-benchmark-2026-11-01.md)의 첫 행동·피드백·결과 보관·재시도 기준을 활용했다. 이번에 타 제품을 직접 플레이하거나 지불 의사를 조사한 근거는 아니다. 결제·광고·구독 구현은 이번 범위가 아니다.

## 공개 범위와 한계

무료 공개 개선을 계속한다. 모델/동작·폰트·vendor의 기존 출처와 라이선스를 보존했고 credits에는 기존 notice 링크를 보강했다. 향후 실제 상업 사용의 도름이 CC BY-NC 조건, Meshy 출처/계약 범위, Open-Meteo 무료 서비스 조건은 [권리·출처 검토](commercial-readiness-2026-11-06.md)에 따로 기록했다. 기술 검수 통과를 곧바로 유료 판매 권리 확보나 수익성 입증으로 표현하지 않는다.

현재 근거는 Chromium 에뮬레이션/소프트웨어 WebGL, 모델·DOM 회귀와 정지 화면 검토다. 실제 iPhone/iPad/Android·Safari, 스크린리더 청취, 스피커 음질, 장시간 발열·배터리·장기 재방문 재미를 전수 검증하지 않았다. 이 한계를 숨기지 않되 실제로 발견하고 재현한 문제부터 고치며 다음 주기를 이어 간다.
