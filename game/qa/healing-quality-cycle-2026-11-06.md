# 힐링·휴식·즐거움 품질 개선 · 2026-11-06

작업 중인 검수 기록이다. 아직 이번 변경 전체를 합격·배포했다고 판정하지 않는다. 이전 공개판은 `2026.11.01.1`이며 이번 기준 소스는 `6039266`이다.

## 합의한 방향

[개선 계획](../docs/healing-quality-plan-2026-11-06.md)에 따라 사용자 경험, 학습, 생활, 놀이·체육, 교통, 디자인, 상업 조건을 나누고 서로의 변경을 검토한다. 편안한 관람도 하나의 완성된 경험으로 인정하되, 조작 놀이에는 읽을 수 있는 판정과 쉬운 재시도를 요구한다.

## 공용 메뉴와 첫 사용

- 휴대폰에서 생활 메뉴를 카메라 조작보다 먼저 배치했다. 확대·회전·기울기는 접고 펼칠 수 있으며, 메뉴를 다시 열면 주 메뉴부터 보인다. 카메라를 펼친 선택은 유지한다.
- 지도 버튼의 전경색 누락을 고쳤다. 실제 DOM 측정 대비는 **1.14:1 → 7.87:1**이다.
- 첫 안내의 ‘호기심을 따라’는 소개한 활동을 선택하는 배움 안내로 연결한다. 쉬기/놀이/배움 필터마다 해당 추천이 남으며 검색 중에는 검색 결과에 집중한다.
- 작은 하루는 실제 간직한 순간부터 보여 주고, 미발견 목록은 선택해서 펼친다. 처음에는 쉬어 갈 곳으로 이어 준다. 로봇·균형 기록은 실제 여러 과제에 맞는 문구로 정리했다.
- 독립 디자인 검토에서 제안한 미술 닫기 고정 방식은 그림 위를 가릴 수 있어 학습 담당자가 하단 돌아가기 버튼으로 바꿨다. 카페·간식의 작은 첫 구도도 별도 개선 대상으로 합의했다.

### 실제 검증 범위

1. `first-impression-dom-review.mjs`: 실제 `ui.js`, `hud.js`, CSS를 사용한 휴대폰 세로/가로·태블릿 세로/가로·컴퓨터 **5/5**. 추천·빈 검색·키보드 펼침/닫기·스크롤 복귀·기존 기록 표시를 확인했다. 게임 렌더러는 실행하지 않으며 저장된 기록 표시는 fixture 검사다.
2. `healing-shell-acceptance.mjs`: 실제 게임의 휴대폰 **390×844·844×390**, 태블릿 **768×1024·1024×768**, 컴퓨터 **1440×900**, 총 **5/5**, 예외/HTTP 오류 0. 첫 배움 안내→로봇방, 피아노 검색→음악실, 쉬기 추천→공원으로 실제 이동했다. 확대·방 맞춤·Escape 메뉴 복귀를 실제 입력으로 확인했다.
3. 같은 실제 게임에서 벤치 가까이만 검수용으로 준비하고 **실제 행동 버튼으로 앉기→기록 발생→일어나기→기록 열기→전체 새로고침 후 기록 보존**을 확인했다. 기록·시간·완료값을 주입하지 않았다. 폰·태블릿·컴퓨터의 각각 새 브라우저 세션에서 기록 보존을 확인했다.

근거: `first-impression-dom-2026-11-06/results.json`, `healing-shell-2026-11-06/results.json`, `healing-shell-tablet-desktop-2026-11-06/results.json` 및 해당 캡처. 소프트웨어 WebGL·화면 크기/터치 에뮬레이션과 낮은 캡처 DPR은 실물 기기의 성능·발열·Safari 검사로 해석하지 않는다.
