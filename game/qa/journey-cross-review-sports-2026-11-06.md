# 체육 수정 독립 검토 · 2026-11-06

검토자: 교통·접근성 담당. 체육 구현자가 아닌 별도 에이전트가 `dist/gym/climbing-controller.js`, `climbing-model.js`, `controller.js`의 현재 diff와 관련 입력·정리 경로를 읽고 `node --test tests/climbing-replay.test.mjs`를 재실행했다. 3/3 통과. 이 검토는 새 실제 3D 완주나 스크린리더 청취의 대체 증거가 아니다.

차단 결함은 발견하지 않았다.

- 클라이밍 완료 뒤 ‘처음 자리로 돌아가기’는 기존 모델의 `stop('retry')`를 사용한다. 실제 지지점 이력을 역순으로 되짚고, 내려오기 세션을 요청하지 않아 같은 기구에서 다시 방법을 고를 수 있다. 일시정지 중 귀환 진행과 입력을 멈추고, 재시작할 때만 `stopReason`을 지운다.
- 되돌아오는 중 ‘나오기’는 기존 `requestExit()`와 안전한 하강을 이어받는다. 완료/되돌아가기/준비/재시작 상태에서 버튼 활성 조건이 서로 맞는다. 버튼 DOM을 교체하지 않아 현재 포커스를 불필요하게 잃지 않는다.
- 클라이밍 상태·점수, 러닝머신 상태·점수의 내용이 같으면 `textContent`를 다시 쓰지 않는다. 매 프레임 같은 live region을 교체하던 원인을 제거하며, 실제 상태·초·점수가 달라질 때는 갱신한다. 안내 문구는 미구현 기능 예고 대신 현재 이용 가능한 느긋한 놀이를 설명한다.
- 검토 중 pointercancel 뒤 다른 버튼이 계속 막힐 가능성을 제기했으나, 패널의 capture 단계 `pointerdown`이 새 제스처마다 `cancelledPointer`를 지우는 기존 경로를 확인했다. 따라서 해당 의심은 철회했다. 취소된 제스처의 compatibility click 억제와 새 tap/키보드 입력은 구분되어 있다.

남는 검증 한계: 3개 새 회귀의 접촉 증거는 격리된 모델 fixture다. 실제 원본 도름이의 지지점/순서와 휴대폰 조작은 체육 담당의 실제 브라우저 증거를 함께 읽어야 한다. 실제 보조공학 음성 출력은 확인하지 않았다.

## 후속 간식 근접 카메라 검토

`amusement/food-cart-camera.js`, `food-cart-order.js`, 관련 CSS와 `game.js`의 camera 선택 두 지점을 별도로 검토했다. `tests/amusement-food-camera.test.mjs` 5개와 `tests/amusement-food-game-lifecycle.test.mjs` 2개를 직접 실행해 7/7 통과했다.

카메라는 도름이/산책 카메라를 바꾸지 않는 별도 인스턴스다. 기존 게임 루프를 사용하고, 취소·숨김·다른 방·폐기 시 getter가 null을 반환한다. RoomManager의 실제 commit에서 `sceneChanged()`를 호출하므로 동일 room의 뷰 교체도 정리된다. 상위 소유권이 있는 비행·배·전망·교실 활동의 기존 조기 반환은 유지되며, 일반 장면의 가시성과 최종 렌더가 같은 간식 카메라를 고른다. 확인한 코드 범위의 차단 문제는 없다.

실제 브라우저에서 ‘전체 보기’ 상태로 간식을 열 때도 확인하도록 구현자에게 요청했다. 가시성 호출의 `overview`는 기존 산책 카메라의 값이므로, 이 조건에서 성벽 정책이 얼굴을 가리는지는 실제 카트 위치의 캡처가 필요하다. 가능성을 지적한 것이며 재현된 결함으로 분류하지 않았다.
