# 저장·복구 독립 검토 · 2026-11-06

기존 일반 저장/재접속·대출 복원·둘째 탭 읽기 전용·BFCache 정책 검사를 반복하는 대신, **느린 초안 복원과 실패 후 재시도에서 사용자 작품을 잃는지**를 추적했다. 계정·서버·새 백업 기능을 추가하지 않았다.

## 발견하고 수정한 문제

### P1 · 미술 초안을 보기도 전에 덮어쓸 수 있음

`art-view.js`는 초안을 비동기로 읽고 PNG를 해석하는 동안 그림 입력과 새 종이를 허용했다. 그 사이 문서가 변경되면 기존 그림을 복원하지 않으면서 `loaded=true`와 저장된 초안의 revision을 채택했다. 이후 저장은 사용자에게 한 번도 보여 주지 않은 기존 그림을 새 획으로 교체할 수 있었다.

첫 읽기가 실패한 뒤 임시 그림을 그렸을 때도 같은 문제가 있었다. 저장 버튼의 재시도가 기존 초안을 찾으면 복원을 생략한 채 그 revision으로 새 그림을 저장했다. 표적 회귀에서 **기존 초안이 발견됐는데도 `storage.write`가 1회 실행되는 것**을 재현했다.

수정 후에는 다음과 같이 동작한다.

- 처음 읽기·이미지 해석 중에는 그림·새 종이·되돌리기·보관을 잠깐 기다리게 하고 상태를 표시한다. 닫기는 계속 가능하다.
- 읽기 실패 후에는 임시 그림과 PNG 보관을 이용할 수 있다. 재시도에서 뒤늦게 저장된 그림을 찾으면 양쪽을 보존하며 자동으로 덮어쓰지 않는다. 임시 그림을 PNG로 보관한 뒤 페이지를 다시 열어 기존 그림을 확인하도록 안내한다.
- 정상 복원 후에는 기존 그림 위에 새 획을 추가하고 저장할 수 있다.
- 이전 창의 늦은 읽기/해석 결과는 새 창에 적용하지 않는다. 읽기 전용에서는 저장된 그림을 읽고 PNG로 보관할 수 있으나 쓰기는 거절한다.

검증: `node --test tests/art-draft-loading.test.mjs`, **수정 전 4실패·1통과 → 수정 후 5/5 통과**, 읽기 거부 이후 빈 저장소로 회복해 임시 그림을 정상 저장하는 추가 검사까지 **최종 6/6 통과**. 실제 `ArtDocument`와 컨트롤러를 사용하며 IndexedDB 응답·PNG 해석·DOM은 시간 순서를 제어하는 모의 구현이다. 이 결과를 실제 터치·그림 픽셀 렌더·IndexedDB 브라우저 완료 증거와 혼동하지 않는다. 정상 저장 브라우저 회귀는 학습 담당자의 후속 실행과 함께 확인한다.

### 수학 초안의 실패 후 재복원 경로

최초 저장 읽기 실패 뒤 임시 수식/분필을 작성한 상태에서 방 이동·재열기가 `restore()`의 재시도를 실행하면, 뒤늦게 읽힌 저장본이 현재 임시 문서를 교체하는 경로를 학습 담당자에게 전달했다. 담당자가 분필 한 획 유실과 입력기 안의 `x+1`이 저장본의 `y`로 교체되는 **2개 실패를 재현**하고 수정했다.

새 복원 경로는 문서의 epoch와 입력기의 editorRevision을 함께 확인한다. 읽기/해석 중 변경도 재확인하고, 임시 작업이 있으면 저장본을 채택하거나 쓰지 않으며 PNG 보관 후 다시 열도록 안내한다. `tests/math-board-start.test.mjs`의 기존 3개와 새 2개를 독립 실행하여 **5/5 통과**했다. 미술 6개와 합쳐 이번 초안 표적 검사는 **11/11**이며 전체 앱 테스트 수와 구분한다.

## 검토한 저장 경계

| 영역 | 확인한 구조 | 이번 검토 범위 |
| --- | --- | --- |
| 진행·사진 | 진행 주본/직전 백업과 사진 JPEG는 **localStorage**다. 사진 메타·벽 배치는 진행에 있고 사진 바이트는 별도 키다. | `save.js`, `save-keys.js`, `photo-storage.js`, `game.js`의 호출 대조. 사진 저장 실패 시 메타 commit 거절과 바이트 rollback, 주본/백업이 가리키는 사진 보존 목록을 확인했다. 새로운 결함은 확정하지 않았다. |
| 단일 작성자 | Web Locks로 현재 origin의 작성자를 하나로 제한한다. 소유하지 못한 탭은 진행 쓰기를 차단한다. | `save-writer.js`, localStorage 래퍼, `transact`, 학교 도구의 `canSave` 전달을 추적했다. BFCache 복귀는 잠금 재획득 없이 읽기 전용으로 남는 기존 정책을 유지한다. |
| 진행 commit | 저장 전 원문/백업 원문 대조와 revision 증가. 실패 시 실행 상태를 성공 상태로 바꾸지 않는다. | 백업만 먼저 쓰인 뒤 주본 쓰기가 실패하는 경로의 retry baseline, 미래 버전/손상 데이터 보호, 마이그레이션/초기화 실패 표시를 소스로 확인했다. 모든 저장장치 오류 조합을 새 브라우저로 실행한 것은 아니다. |
| 그림·수식 | 각각 별도 IndexedDB 초안, 저장된 revision 대조 후 트랜잭션 완료를 기다린다. | `art-storage.js`, `math-board-storage.js`의 미래 버전/손상·충돌·읽기 전용 처리, 요청 중 쓰기 권한 재확인, 컨트롤러의 인코딩/저장 완료 표시를 추적했다. 미술 복원 경합을 새로 재현·수정했다. |
| 실패 안내 | 실패한 진행 commit은 수확·소비 성공으로 처리하지 않는다. 작품 저장은 저장한 epoch와 이후 편집을 구분한다. | 생활 독립 회귀 6개에서 사진 삭제 실패의 앨범/벽 보존, 편지 보내기 실패의 선물 보존, 읽음 저장 실패에도 기존 편지 열람 허용을 확인했다. |
