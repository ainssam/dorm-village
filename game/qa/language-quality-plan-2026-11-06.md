## 실제 실행 방법과 근거의 경계

도구는 실제 지도 버튼으로 교실에 들어간다. QA의 가까운 위치 준비는 충돌·가시선 검사를 통과한 위치만 사용하고, 실제 E/상호작용 버튼으로 도구를 연다. 방 이동·학습 상태·정답·시간·완료를 브리지에서 주입하지 않는다. 질문의 **답은 저장소 내용에서 읽어 버튼을 선택하는 QA solver**다. 사람이 스스로 이해하거나 재미를 느꼈다는 증거가 아니며 입구부터 모든 보행을 완료한 검사도 아니다.

기본은390×844 touch, DPR1, 일반 움직임의 전체 문항이다. `QA_FULL=0`은 맞춤법·자모·뜻풀이·듣기·문장 각2문항과 대화 대표 경로만 실행하며 전체 완료로 기록하지 않는다. PC1440×900, 작은폰320×568, 가로844×390, 태블릿768×1024는 대표 흐름/읽기를 별도로 실행한다. 태블릿 대표는 `QA_REDUCED=1`을 적용한다. 한 번에3D 브라우저 하나만 실행한다.

```sh
QA_OUT=qa/language-quality-acceptance-2026-11-06/touch node scripts/language-quality-acceptance-2026-11-06.mjs
QA_DESKTOP=1 QA_FULL=0 QA_OUT=qa/language-quality-acceptance-2026-11-06/desktop node scripts/language-quality-acceptance-2026-11-06.mjs
QA_WIDTH=320 QA_HEIGHT=568 QA_FULL=0 QA_AUDIO_FAILURE=1 QA_LANGUAGES=english QA_OUT=qa/language-quality-acceptance-2026-11-06/audio-failure node scripts/language-quality-acceptance-2026-11-06.mjs
```

기본 실행은 영어 음성을 자동 재생하지 않고 transcript만 사용한다. `QA_AUDIO_FAILURE=1`은 영어 녹음 파일의 요청만 의도적으로 실패시킨 뒤 일반/느리게 재시도와 글자 자동 펼침·중지를 확인한다. 이 실패는 외부 서비스 장애를 우연히 관측한 것이 아니다. 음성의 실제 청취·발음·스피커 음질은 별도다. 화면의 마을 소리 버튼은 배경음 선택이므로 영어 전체 음소거라고 해석하지 않는다.

각 실행 전후 dist 전체 SHA를 대조하고 질문별 피드백·정답 선택·지도/근접 준비·실패/예상 실패를 남긴다. 정상 진행과 의도한 녹음 실패를 섞어 ‘오류0’으로 표현하지 않는다. 스크립트는 현재 준비만 끝났고 실행 권한 신호를 기다린다.

## 비판적 내용·접근성 판정

[독립 내용 검토](language-content-review-2026-11-06.md)는 명확한 사실·정답 오류를 찾지 못했다.49개 음성 항목의98파일 존재와40개 내용-음성문자열 연결을 확인했지만 실제 발음을 청취한 것은 아니다. 원래 자모 설명의 첫소리ㅇ/받침ㅇ 구분, 한글1443/1446과28/24 구분, 두 정중한 답의 동등한 인정은 유지할 가치가 있다.

다음 구현이 허용되면 우선 작은 접근성 수정 두 가지를 권한다. 역할대화의 선택 그룹 이름이 음료 그림/이동 단계에서도 ‘내가 할 말 고르기’로 남으므로 실제 과제에 맞춘다. 완성 문장 `.english-answer`의 p와 카페 대화 세 위치·순번이 붙은 길 안내의 영어 부분 span에 `lang="en"`을 지정한다. 일상표현 영어 문단은 `renderDictionary()`에서 이미 언어가 표시되어 있으므로 수정 대상이 아니다. `some water`의 설명은 요청을 뜻하는 문장 전체와 양을 정하지 않는 명사구를 구분하도록 낮은 우선순위로 정밀화한다. 지금 `.3` 소스에는 적용하지 않았다.

선택지 섞기는 현재 보완의 필수 조건으로 삼지 않는다. 초보자가 같은 위치를 다시 찾아보는 것도 유용하며, 문항만 섞어서 새 학습 콘텐츠가 늘었다고 소개하면 안 된다. 실제 실행에서 재도전의 가치나 반복 피로 문제가 드러난 뒤 선택적인 복습 변주를 판단한다.
