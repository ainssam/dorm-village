# 최종 음악 조작·공간 시각 검수 · 2026-11-01

## 방법과 범위
현재 앱과 실제 음악 모듈을 로컬 Chromium에서 실행했다. 피아노·하프·첼로를 휴대폰 세로 390×844, 휴대폰 가로 844×390, 태블릿 가로 1024×768에서 열어 터치 입력·정지/재개·닫기를 실행했다. 도구 진입 위치만 테스트 브리지로 설정했고 연주/닫기에는 실제 DOM과 터치 입력을 사용했다. 별도의 1440×900 화면에서 6개 요청 공간을 전환 잠금이 풀린 뒤 1.2초 후 캡처했다.

DPR 0.5의 소프트웨어 WebGL이다. CSS 레이아웃 크기는 원래 기기 규격을 유지한다. 유휴 프레임 샘플링으로 CPU 부하를 낮추되 스크린샷 시작부터 종료까지 모든 렌더 호출을 정상 실행하고 연속 두 프레임을 기다렸다. 캡처를 직접 열어 보았으며 빈 렌더를 합격으로 처리하지 않았다. 실물 휴대폰 GPU·iOS Safari·실제 스피커 음질 시험은 아니다.

재현 스크립트: `scripts/final-visual-detail-2026-11-01.mjs`. 첫 결과와 화면: `qa/final-visual-detail-2026-11-01/`.

## 1차 결과
- 3악기 × 3규격 9회에서 실제 음 선택/활 제스처, 피드백, 정지·재개, 닫기와 입력 잠금 해제가 동작했다. 닫기 버튼은 모든 규격에서 화면 안에 있고 44px 이상이다.
- 추가 6개 공간 진입도 정상이며 JS 런타임·console error·HTTP 실패는 모두 0건이다.
- 이 기능 통과만으로 시각 합격을 판정하지 않았다. 아래 P1 시각 회귀를 확인해 통합 담당자에게 전달했다.

### P1: 음악 3D 영역이 크림색으로 가려짐
`dist/release.css`의 `dialog:not(.village-map)` 배경색이 `dialog.music-workshop`의 투명 배경을 덮었다. 그 결과 연주 입력은 되지만 캐릭터·악기 3D 화면이 모두 가려졌다. 피아노·하프·첼로에 공통으로 나타나며 `throw-workshop`도 같은 구조다. 증거: `phone-portrait-piano-opened.png`, `phone-portrait-harp-opened.png`.

필요 수정: 3D 화면을 비워 두는 음악·공 던지기 dialog를 일반 크림색 배경 규칙에서 제외. 수정 후 새 브라우저 캡처와 computed background 검사를 수행한다.

### P2: 휴대폰 가로 화면에서 연주 패널이 짧음
844×390에서 피아노 건반은 y=280부터 높이 148px로 하단이 처음 화면 밖에 있다. 첼로 활도 첫 화면 아래에 접힌다. 내부 스크롤로 터치할 수는 있지만 첫 사용자의 발견성이 떨어진다. 증거: `phone-landscape-piano-opened.png`, `phone-landscape-cello-opened.png`. 짧은 가로 화면에 3D/조작 패널을 좌우로 배치하는 개선을 전달했다.

## 수정 후 재검증 · 통과

수정 범위는 `dist/release.css`의 음악/공 던지기 투명 예외와 짧은 가로 화면 음악 레이아웃으로 한정했다. 일반 dialog의 크림 배경 규칙에서 두 종류를 제외하고 투명 배경을 명시했다. 높이 520px 이하·너비 621px 이상에서는 3D 영역과 조작 패널을 좌우로 배치한다. 패널의 최소 너비 404px를 확보해 8개의 음 버튼도 지나치게 작아지지 않게 했으며, 짧은 화면의 피아노 건반과 부가 설명 크기를 조정했다.

새 결과: `qa/final-visual-detail-fixed-2026-11-01/results.json`.

- **음악 9/9 실제 브라우저 흐름 통과**, JS 런타임·console error·HTTP 실패 **0건**.
- 모든 열린 음악 dialog의 computed background가 `rgba(0, 0, 0, 0)`임을 검사했다.
- 새 `*-opened.png` 9장을 모두 직접 열어 도름이와 피아노·하프·첼로가 실제로 보이는지 확인했다.
- 휴대폰 가로 피아노 첫 건반은 y=128~254, 높이 126px로 화면 안에 모두 들어온다. 음역·소리·잠깐 쉬기·낮은/높은 쪽·닫기도 첫 화면에서 보인다.
- 휴대폰 가로 첼로는 8개 음 선택·활·소리·멈추기·음량·닫기가 첫 화면에서 보이며, 실제 터치 활 제스처와 정지/닫기를 완료했다.
- 세로 휴대폰과 태블릿의 3D/조작 배치는 유지되며 해당 6회에서도 연주·닫기가 동작했다. 페이지나 dialog의 가로 넘침은 없다.
- 1차에서 발견한 음악 P1과 가로 배치 P2는 해결됐다. 베이커리 첫 시점의 작은 캐릭터는 공간 전체보기의 P2 관찰 사항으로 남긴다.

캡처 중에는 항상 연속 정상 렌더를 사용했다. 재현 스크립트는 이후 비캡처 샘플 프레임에서도 clear와 render를 함께 보존하도록 추가 정리했으며 문법 검사를 통과했다. 기능 결과는 실제 DOM/터치 상태와 새 화면에 근거한다. 실제 스피커를 듣는 음질 평가, 실물 GPU 성능, 다른 브라우저 인증으로 확대 해석하지 않는다.
