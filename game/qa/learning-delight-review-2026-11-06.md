# 학습·창작 공간 품질 개선 · 2026-11-06

힐링·휴식·즐거움을 기준으로, 과제를 늘리기보다 첫 결과물이 깨끗하게 보이고 잘못 눌러도 고칠 수 있으며 만든 것이 안전하게 남는지를 검토했다.

## 제품 변경

- **수식 칠판 첫 산출물:** 새 초안은 빈 칠판으로 시작한다. 복잡한 수업 예시와 새 수식이 겹치던 문제를 없앴다. ‘예시 밑그림 보기’로 직접 켤 수 있고 되돌리기도 된다. 기존 저장본의 예시 표시 설정은 유지한다.
- **교실 풍경과 개인 작품 구분:** 미편집 초안은 실제 교실의 예시 칠판을 지우지 않는다. 사용자가 편집한 칠판이나 저장된 칠판만 교실에 반영한다. 저장된 빈 칠판도 작품으로 인정하며, 초기화하면 교실 예시를 복원한다. 저장소 읽기 실패를 새 작품으로 취급하지 않는다.
- **미술 종료 동선:** 저장·PNG 보관 아래에 ‘마을로 돌아가기’를 추가했다. 떠다니는 닫기 버튼이 그리는 종이를 가리지 않도록 일반 문서 흐름에 둔다.
- **건강정보 분류:** ‘검토 시작 가능’과 ‘추가 확인 필요’는 같은 자료에 둘 다 해당할 수 있었다. 쟁반을 ‘출처를 따라 확인할 수 있어요’와 ‘확인할 출처부터 찾아요’로 구분했다. 자료 B도 사실 확인이 필요하다는 해설은 유지한다.
- **느린 미술 초안 복원 보호:** 독립 저장 감사에서 발견한 P1. 기존 그림을 읽고 해석하기 전에 그리기·새 종이·저장을 실행하여, 한 번도 보지 못한 기존 그림을 덮을 수 있었다. 읽기/해석 중 입력을 기다리며, 읽기 실패 후 만든 임시 그림은 뒤늦게 발견한 저장본과 함께 보존한다. `art-draft-loading.test.mjs`의 재현 및 수정은 독립 감사 에이전트가 담당하고 학습 담당이 교차 검토했다.
- **수학 읽기 재시도 보호:** 독립 감사가 제보한 P1을 추가 재현했다. 최초 읽기 실패 후 만든 분필 그림과 입력 중인 식이, 다음 방문에서 찾은 옛 저장본으로 교체되었다. 현재 문서 변경과 입력기 변경을 함께 확인하여 임시 작업과 기존 저장본을 보존하고 PNG·수식 원본 보관 방법을 안내한다. 그림 유실 및 `x+1`이 옛 `y`로 바뀌는 두 실패를 실제 컨트롤러 회귀로 재현한 뒤 수정했다.

## 실패를 구분한 기록

- 초기 수학 예시 undo 검사에서 최종 그리기를 기다리지 않은 즉시 PNG 비교가 실패했다. 정상 그리기 두 프레임 뒤 모델 상태와 RGBA를 함께 확인한 진단은 false/0픽셀→true/16146픽셀→false/0픽셀이고 최초 PNG와 일치한다. 제품 undo 코드는 바꾸지 않았으며, 이 근거만으로 일반 기기의 렌더링 결함을 확정하지 않았다. 진단: `learning-math-diagnostic-2026-11-06/`.
- 3D 교실 칠판 검사 최초 훅이 연결 학교의 `zoneView()` 대신 전체 `view`를 읽어 null이었다. QA 훅만 올바른 공간 뷰로 고쳐 실제 칠판 검사를 통과했다. 최종 근거는 `learning-classroom-display-2026-11-06/`다.
- 미술 저장 보호 수정 후 정상 저장·PNG와 지연 읽기, 수학 실패 후 복구의 실제 브라우저 검증은 아래 후속 결과에 별도로 기록한다.

## 회귀·교차 검토

`node --test tests/math-board-start.test.mjs` 5/5. 새 초안·기존 저장표시·교실장식 보존·저장빈판·읽기실패·초기화·임시분필/입력식 보존을 실제 모델/컨트롤러로 검증한다. 수학 임시작업 보호 두 사례는 수정 전 실패했다.

독립 감사 에이전트가 수학 변경을 재검토했고, 학습 담당은 미술 저장 보호와 클라이밍 재시작 변경을 교차 검토했다. 클라이밍 신규 회귀3/3도 별도 실행했으며 실제 GLB 접촉 검증은 체육 담당의 브라우저 증거와 구분한다. 도서관의 분류 책장 안내도 실제 표지·미션 대상·분류 연출과 대조했다.

## 저장 보호 후속 검증 · 통과 범위와 남은 문제

- **수학 최종 정상/복구 두 흐름 통과:** `learning-storage-final-2026-11-06/results.json`의 `math-formula-save-export`, `math-unavailable-store-preserves-temporary-work`. 실제 UI로 저장한 기존 수식이 있는 상태에서 저장소의 `read` 실패만 주입했다. 새 `x+5`를 칠판에 놓고 `z+2`를 입력기에 남긴 뒤 읽기를 복구해 재입장했다. 두 임시 작업이 유지되고 기존 저장본을 덮지 않으며, 임시 칠판의 실제 PNG를 내려받았다. 전체 새로고침하면 원래 저장 수식이 그대로 복원된다. 임시 PNG를 직접 열어 `x+5`가 그려졌음을 확인했다. 레코드·점수·진행 상태는 주입하지 않았다.
- **미술 정상 저장/PNG 통과:** 저장 보호 수정 뒤 `learning-art-single-input-2026-11-06/results.json`의 `art-touch-undo-save-export`가 실제 터치 획·undo/redo·저장·전체 새로고침·PNG를 통과했다. 앞선 `learning-art-storage-final-2026-11-06/`의 같은 정상 흐름도 통과한다.
- **미술 지연 저장 전체 흐름은 아직 보류:** 기존 저장 그림이 있다는 전제를 확인하고 읽기를 지연하는 동안 새 획/새 종이/저장/내보내기가 막히는지, 지연 해제 후 기존 픽셀이 정확히 돌아오는지는 확인됐다. 이후 새 획을 더하고 저장하는 터치에서 `pointerdown`/`pointerup`은 왔지만 `click`이 발생하지 않아 저장 상태 대기가 실패하는 실행이 있다. 실제 UI 상태를 성공으로 주입하거나 버튼 이벤트를 강제 호출하지 않았다.
- **입력 원인 분리:** 처음에는 CDP 획 입력과 Playwright 버튼 입력의 세션 혼합을 의심했다. 한 CDP 세션으로 양쪽을 보낸 대조(`learning-art-single-input-2026-11-06`)에서도 지연 흐름의 저장 터치가 실패했으므로, 세션 혼합을 원인으로 확정하지 않는다. 초기 `learning-art-storage-proof-2026-11-06/`의 undo 터치 역시 down/up 뒤 click 누락을 기록했다. 제품의 저장/undo 로직을 바꾸거나 무조건 pointerup에서 실행하는 우회 코드는 넣지 않았다. 최신 원시 결과의 `artEvents`에 실제 이벤트 기록을 보존했다.
- `art-draft-loading.test.mjs` 6/6와 `math-board-start.test.mjs` 5/5를 독립 교차 실행했다. 이는 저장소 지연/실패 상태의 컨트롤러 회귀 통과이며, 위의 아직 분리되지 않은 네이티브 터치 클릭 누락을 대신해 합격시키는 근거가 아니다.
- 미술 종이 내부에는 `aria-busy=true` 동안에만 ‘저장된 그림을 불러오는 중이에요…’ 시각 안내를 표시한다. 기존 live status는 유지하며 안내 자체는 포인터를 받지 않는다.
