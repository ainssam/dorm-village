# 첫 경험·메뉴 디자인 독립 검토 · 2026-11-06

판정 기준은 **힐링·휴식·즐거움, 놀다가 만나는 작은 배움**이다. 기능 수를 늘리기보다 처음 할 일을 찾고, 조작 결과를 이해하며, 편하게 그만두는 경험을 우선한다. 이 보고서는 내부 디자인 검토이며 실제 이용자의 재미·재방문·지불 의사를 입증하지 않는다.

## 유지할 장점

- 크림 바탕에 민트·살구·라벤더를 쓰면서 본문은 진한 색으로 읽기 쉽다. 색 수를 더 늘릴 필요는 없다.
- Pretendard 본문과 손글씨 제목의 역할이 나뉘어 있고, 주요 버튼은 대체로 44px 이상이다.
- 처음 안내에 가입/기록 범위와 기기별 조작이 있다. 전체 모달을 더 길게 늘리기보다 초기 선택을 구체화하는 편이 유리하다.
- 쉬기·놀이·만들고 배우기라는 의도별 분류는 모토와 잘 맞는다. 추천 시간은 제한 시간이 아니라고 명시한다.
- HUD는 비모달 disclosure이고 Esc로 닫으며 메뉴로 포커스를 돌려준다. 전역 모달은 닫을 때 호출 위치로 포커스를 돌려주는 경로가 있다. 실제 보조공학 합격으로 확대하지 않는다.

## 피해야 할 방향

학교라는 이유로 모든 휴식에 문제·정답·도장을 붙이지 않는다. 출석 연속일·손실 회피 보상·기록 채우기를 도입하지 않는다. 지도·가방·작은 기록의 발견 가능성을 높이는 것이 새로운 대시보드나 새 화폐보다 우선이다. 파스텔 장식과 이모지는 읽기와 목표 식별을 도울 때만 쓰며, 색만으로 상태를 전달하지 않는다.

## 다음 검수

수정은 공용 UI 담당이 적용한 뒤 독립 검토한다. 정적 대비 측정과 별도로 폰/태블릿/컴퓨터에서 **첫 안내 → 의도 선택 → 소개한 활동 찾기 → 실제 반응 → 종료**, 메뉴·필터·기록의 키보드 이동, 좁은 가로 화면을 확인해야 한다. 현재 보고서만으로 그 흐름을 합격 처리하지 않는다.

이 변경 범위에서 차단할 회귀는 발견하지 않았다. 후속 검토에서 지적한 `world/activities.js`의 `school-seat` ‘오늘의 숙제’ 표현도 공용 담당이 수정했다. 전체 플레이 동선은 별도 통합 브라우저 검수로 판정한다.

공용 담당의 하늘 보기 글자 크기 통일과 HUD 다시 열기 동작 수정 뒤 **같은 5규격을 최종 재실행해 5/5 통과**했다. 카메라 도구를 실제 Enter로 펼치고 버튼을 누른 뒤 패널을 아래로 스크롤하는 fixture를 만들었다. 실제 Esc → 메뉴 클릭으로 다시 열었을 때 `scrollTop=0`, 놀이 안내가 패널 안에 표시, `aria-expanded=true`, 닫기 버튼 포커스, 카메라 도구의 펼침 선택 유지까지 확인했다. 결과 파일은 이 강화된 최종 실행으로 갱신했다.

## 공간·결과물 추가 시각 검토

새 기능을 제안하기보다 기존 놀이가 눈에 잘 보이는지를 기준으로 대표 PNG를 직접 열었다. 아래 두 개선 후보는 이전 캡처를 근거로 하며, 수정 후의 최종 화면 판정은 담당자의 새 정상 렌더 결과를 기다린다.

1. **카페의 첫 구도.** `final-visual-detail-2026-11-01/settled-bakeryCafe.png`의 720×450 캡처에서 건물은 약300×220px, 도름이는 약10px다(검수 렌더 절반 크기이므로 CSS 화면은 두 배). 2층 바닥이 1층 작업대를 가려 첫 방문자가 빵 굽는 위치를 읽기 어렵다. `dist/bakery/entry-frame.js`는 처음 전체 건물 bounds로 reframe하고 첫 움직임 뒤에만 일반 follow로 바뀐다. 생활 담당이 이 동작과 실제 계단·2층 이용을 함께 검토 중이다. 바닥/벽을 모두 없애기보다 현재 층과 도름이가 읽히는 초기 구도, 전체 보기는 사용자의 선택으로 남기는 방향이 적합하다.
2. **놀이섬 간식의 작은 결과.** `amusement-review-2026-11-01/21-snack-hotdog-held.png`에서 ‘핫도그를 들었어요’라는 안내는 있지만 섬 전체 구도여서 손의 간식 형태를 식별하기 어렵고 도름이의 뒤통수·상점이 주로 보인다. 역할놀이의 실제 결과인 받기·먹기를 가까이 보여줄 여지가 있다. `dist/amusement/food-cart-order.js`와 기존 카메라 소유권을 확인한 뒤, 주문 중의 구도와 취소/종료 뒤 원래 시야 복귀를 같이 검증해야 한다. 놀이 담당에게 공유했다. 기능 고장으로 확정한 항목은 아니다.

`full-review-2026-11-01/amusementIsland.png`의 성은 큰 입구 랜드마크로 읽히며 현재 팔레트를 통째로 다시 바꿀 근거는 부족했다. `amusement-review-2026-11-01/01-claw-start.png`에서는 목표 인형·집게·방향 조작이 동시에 보인다. 새 `learning-delight-2026-11-06/math-export.png`와 `math-formula-rendered.png`는 첫 수식이 깨끗한 녹색 칠판에서 읽히며, `art-bottom-return.png`는 저장/보관 다음에 돌아갈 버튼이 있다. 이 결과물에는 장식을 더 넣기보다 현재 읽기·보관 흐름을 유지하는 편이 좋다.

### 카페 수정의 교차 검토

첫 시안 `cafe-healing-quality-2026-11-06/mobile/cafe-first-entry.png`는 도름이가 커졌으나 첫 작업대가 화면 밖으로 나가서 첫 행동 찾기에는 부족하다고 피드백했다. 단순 확대 대신 1층의 실제 이용 범위를 보여주는 중간 구도로 조정했다.

다음 새 **DPR 1** 화면을 직접 열어 최종 구도를 판단했다.

- `cafe-healing-quality-2026-11-06/entry-final/cafe-entry-1440x900.png`: 반죽 작업대·계단·도름이가 함께 읽히고 2층 바닥의 가림이 해소됐다.
- 같은 폴더 `cafe-entry-844x390.png`: 가로 폰에서도 첫 동선과 행동 버튼이 가려지지 않는다.
- `cafe-healing-quality-2026-11-06/entry-reviewed/cafe-entry-390x844.png`: 세로 폰은 중앙 1층 범위를 택해 도름이가 약40px로 읽히며 반죽 작업대·계단 초입을 함께 볼 수 있다. 곁의 진열장 일부가 잘리는 것은 첫 방문에 필요한 정보 보존을 위해 수용할 수 있다.

따라서 **이 세 구도의 첫 화면 시각 검토는 합격**이다. `entry-frame.js`의 diff에서 첫 보행 뒤 가까운 일반 follow로 복귀하는 흐름과 수동 카메라 선택을 우선하는 조건이 유지됨을 읽었다. 실제 2층의 차 받기·친구 합류·나누기·퇴장 완주는 생활 담당의 별도 실행 근거를 따른다. 본 시각 검토가 그 실행을 대체하지 않는다.
