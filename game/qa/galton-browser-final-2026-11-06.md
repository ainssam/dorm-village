# 갈톤보드 · 실제 앱 흐름 검수

2026-11-06 KST · `2026.11.06.3` 검수판. **공용 창 스크롤·시작 초점 보완까지 반영한 동일 소스로 세 대표 실행을 다시 돌려 모두 통과했다.** 실제 갈톤 도구 사용과 시작 안내·안전한 초기화 취소의 검수이며, 배포 완료나 모든 메뉴·실물 기기 합격을 뜻하지 않는다.

별도 [DOM/2D 검수](galton-discovery-review-2026-11-06.md)와 달리, 이번에는 전체 게임을 켜고 실제 지도에서 **별빛 학교 → 수학실**을 골랐다. 보드 가까이에 충돌을 통과하는 위치만 준비한 뒤, 터치 행동 버튼 또는 키보드 E로 도구를 열었다. 입구부터 보드까지 모두 걸었다는 근거는 아니다. 구슬의 시간·확률·수량·결과와 저장은 주입하지 않았다. 원래 학교 장면의 프레임만 모형을 진행한다.

## 대표 흐름

| 화면·입력 | 실제 완료와 확인 |
| --- | --- |
| 320×568, 터치 | 30개 시작 → 정지/재개 → 완료 → 같은 수로 다시 30개 → 이전 결과 비교 → 100개 중간 정지/비율 확인 → 100개 완료. 현재/직전 분모와 8회 선택의 이론 확률을 표에서 대조했다. |
| 1440×900, 마우스·키보드 | E로 보드 열기, Enter 시작, Escape 종료. 30개 두 번 완료와 비교, 진행 중 종료 후 재열기, 학교 층을 떠났다 돌아오기, 마을 방향키 이동 복귀. |
| 390×844, 터치·움직임 줄이기 | ‘그림 속 구슬 움직임 감추기’가 처음부터 선택됨. 30개 두 번 완료와 비교, canvas 위 native swipe, 종료/재열기·층 이탈 후 초기 상태·스틱 이동 복귀. |

세 실행 모두 현재와 직전 결과를 섞지 않았고, 중간에 닫으면 모형이 멈추고 같은 보드를 다시 열 때 이어졌다. 학교 2층을 나갔다 돌아오면 새 모형이 만들어져 30개 준비 상태와 빈 이전 결과로 돌아왔다. 완료 시 대기 0·이동 0·도착 전체 수, 9칸 합계와 완료 문구를 함께 확인했다. 실제 결과가 우연히 같아도 실패로 취급하지 않았다.

세 화면에서 시작 안내 제목에 보이는 초점이 놓이고, 다음 Tab이 첫 번째 공원 경로로 이동했다. 실제 설정에서 초기화 확인창을 열면 **취소**에 보이는 초점이 놓였다. 취소 후 입력 잠금이 풀렸고 주 저장과 백업의 바이트가 그대로였다. 삭제 동작은 누르지 않았다.

Native touch는 CDP의 touchStart/Move/End로 입력했다. canvas 위에서 시작한 실제 세로 swipe가 공용 모달을 스크롤하고 가로 넘침은 없었다. 선택기는 Playwright `selectOption`으로 변경했으므로 운영체제의 선택창 자체를 손가락으로 열고 고른 검수로 확대하지 않는다. PC의 E/Enter/Escape는 실제 키 입력이다.

## 발견과 보완

첫 시도의 지도 탐색은 숨겨진 수학실 버튼을 곧바로 찾는 harness 가정 때문에 중단됐다. 지도의 학교 건물을 먼저 고르는 실제 흐름으로 고쳤고 `attempt-touch-320-map-discovery`에 이전 기록을 보존했다. 제품 고장으로 세지 않았다.

이어 실제 수학실을 열자, 길게 스크롤했던 학교 지도 위치가 새 도구 창에도 남아 제목과 시작 버튼이 보이지 않았다. 독립 DOM 셸에서는 드러나지 않은 공용 `ui.js` 문제였다. 첫 화면의 제목·시작 버튼 위치를 실제 검수의 필수 assertion으로 추가했다. 수정 전의 수량 흐름 통과는 `pre-scroll-fix-touch-320`에 보존하며 최종 첫 화면 합격으로 승격하지 않는다.

첫 보완 후 추가 시작 안내 확인에서 320×568의 기존 autofocus 버튼 ‘마을 둘러보기’가 y754–803에 남아 보이는 창 y16–552 밖에 있었다. 첫 제목은 보이지만 키보드 초점이 보이지 않는 후속 지적이다. [수정 전 관찰값](galton-modal-first-view-2026-11-06/startup-320.json)과 [화면](galton-modal-first-view-2026-11-06/startup-320.png)을 남겼다. 이 시점의 갈톤 실행은 `pre-focus-fix-*`에 보존했다.

최종 공용 `open()`은 명시적 autofocus가 없는 새 창만 `showModal()` 직후 맨 위로 보낸다. 시작 안내는 제목으로 autofocus를 옮기고, 초기화 확인은 취소 버튼의 native autofocus·스크롤을 유지했다. 담당자가 수정한 뒤 세 실행을 새 컨텍스트에서 모두 재검수했다. 최종 320px에서 시작 제목 y157–227, 다음 Tab의 공원 경로 y389–462, 초기화 취소 y399–447이 창 안에 보인다. 지도에서 들어온 갈톤은 `scrollTop=0`, 제목 y31–64.6, 시작 버튼 y263.3–330.0이다. 각각 [시작 제목](galton-discovery-acceptance-2026-11-06/final-touch-320/startup-before-dismiss.png), [다음 Tab](galton-discovery-acceptance-2026-11-06/final-touch-320/startup-first-tab.png), [취소 초점](galton-discovery-acceptance-2026-11-06/final-touch-320/reset-cancel-focus.png), [갈톤 첫 화면](galton-discovery-acceptance-2026-11-06/final-touch-320/ready.png)을 보존했다.

## 근거의 범위

[요약 JSON](galton-browser-final-2026-11-06.json)에 화면·입력·완료 수·정지/복원·실제 칸 수·초기 위치·시작/취소 초점·오류·소스 지문과 추려 둔 파일 목록을 기록했다. 세 실행의 `dist/` 854개 파일 SHA-256은 서로 같고 각 실행 전후에도 변하지 않았다. 전체 경로→해시 객체를 정렬한 JSON의 SHA-256은 `b0efe4c1d6124950ed6347e0dd6b0c9715e45f20e83f0e66858365ddd1a25ede`다. 공용 `dist/ui.js`는 `aefb4119cb43e5211d12a7738e57611b81ae3df48a667832dc4b48e42b3d9b35`다. 페이지 오류, console error, HTTP 400 이상 응답은 각 실행에서 0이었다. 테스트 수나 구슬 수를 완주한 메뉴 수로 환산하지 않는다.

최종 폴더는 `final-touch-320`, `final-desktop`, `final-reduced-390`이며, 각각 `results.json`, `health.json`, `observations.json`, `runtime-start.json`, `runtime-end.json`과 캡처를 남겼다. 갈톤 동선에 걸린 시간은 각각 약 54.7초, 57.8초, 34.5초이며 소프트웨어 렌더러의 처리량에 영향을 받으므로 사용자 기기의 소요 시간으로 해석하지 않는다. [100개/직전 30개 표](galton-discovery-acceptance-2026-11-06/final-touch-320/100-versus-30.png)와 [PC 첫 화면](galton-discovery-acceptance-2026-11-06/final-desktop/ready.png)도 확인했다.

Chromium의 headless·software WebGL, DPR1, 12회 중 한 번의 3D 렌더 표본화를 사용했다. 상태·입력·시뮬레이션 시간은 바꾸지 않았고 캡처 시에는 정상 렌더를 요청했다. ‘그림 속 구슬 움직임 감추기’는 도구 canvas의 구슬에 적용되며 배경 3D 전체의 정지 기능은 아니다. 이 결과는 실물 휴대폰/Safari 성능, 실제 스크린리더 청취, 장기 재미·학습 효과를 입증하지 않는다. 300개 전체 완료나 실제 새로고침 후 복귀도 이번 대표 실행 범위에 없다. 300개 선택/표 폭과 초기화는 별도 DOM·계약 검사 범위다.

재현 스크립트는 `scripts/galton-discovery-acceptance-2026-11-06.mjs`다. 로컬 서버를 연 뒤 기본값은 320×568 터치와 30/30/100 완료이며, `QA_DESKTOP=1 QA_FULL=0` 또는 `QA_REDUCED=1 QA_WIDTH=390 QA_HEIGHT=844 QA_FULL=0`으로 나머지 대표 실행을 고른다. 실행마다 별도의 `QA_OUT` 폴더를 지정한다. 각 실행의 `harness-used.mjs`는 같은 검사 코드이며 SHA-256은 `ddc8502de2bcc7267aadf37c4c527cc2d9bd60e72ed283b4d18d6a879fc840ae`다. 전체 패키지 검사와 실제 배포 판정은 통합 출시 기록에서 별도로 관리한다.
