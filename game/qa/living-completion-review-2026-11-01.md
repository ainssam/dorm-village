# 생활 기능 완료 흐름 추가 검토

검토일: 2026-11-01. 이전 [생활·야외 소스 감사](living-world-review-2026-11-01.md)의 입장 확인을 보완한다. 대상은 도서관 책 찾기 의뢰 1건, 선물 케이크와 답장, 사진 촬영과 집 벽 액자, 카페 첫 손님 서빙, 새 ‘오늘의 작은 발견’ 게시판에서 실제 장소 이동이다.

## 방법과 판정 기준

`scripts/release-extras-2026-11-01.mjs`를 `scripts/audit-browser.mjs`의 `QA_EXTRA=1`로 실행한다. 공간 전환과 도구 시작에는 QA 진입 훅을 사용하지만, 선택·제작·사진·보상·저장은 실제 UI를 사용한다. 도서관에서는 책장/배달 원 중심에서 1.02 떨어진 위치에만 QA로 배치하며, 마지막 접근은 실제 키보드 또는 터치 스틱으로 수행한다. 모델 상태·시간·재료·보상은 주입하지 않는다.

- 도서관: 원 밖에서 이동 → 책장 살펴보기 → 실제 본문 읽기 → 손에 들기 → 친구 앞 원으로 이동 → 책 배달 → 도장 저장 → 책 속 근거 확인 → 다시 의뢰 목록에서 저장된 도장 확인.
- 선물: 반죽·굽기·장식 → 완성 케이크 → 우체국에 동봉 → 답장 읽기 → 케이크 1개만 소비되고 같은 편지를 중복 전송할 수 없는지 확인.
- 사진: 실제 3D 미리보기 → 촬영 이미지 → 액자 저장 → 집 왼쪽 벽 선택 → 귀가 화면 및 사진첩의 배치 ID 확인.
- 카페: 영업 → 첫 주문의 빵 접기·굽기·음료 만들기 → 진열·서빙 → 손님 1명 완료와 코인 → 쉬기 상태에서 영업 시간이 멈추는지 확인.
- 게시판: 오늘 카드의 제목·본문 확인 → 이전 날짜 → 오늘로 복귀 → 데이터의 `play.roomId`와 목적지 매칭 → ‘장소로 가기’ 실제 이동 후 잠금 해제·모달 닫힘 확인.

브라우저 결과는 각 시나리오의 JSON과 CSS 크기 PNG로 남긴다. 런타임 오류와 가로 넘침을 함께 확인한다.

## 환경의 한계

검증 환경은 headless Chromium과 SwiftShader 소프트웨어 렌더러다. `QA_RENDER_SCALE=.35`로 실제 그리기 해상도를 낮추고 `QA_RENDER_EVERY=12`로 화면 그리기만 12번 중 한 번 수행한다. 입력·모델 업데이트·게임 시간은 원래 루프를 유지하며, 캡처 직전에 정상 draw를 강제한다. CSS viewport 크기와 터치 여부는 별도로 지정한다. 따라서 이 결과는 기능 동작·배치·저장 연결의 증거이며 실물 기기의 프레임 속도·발열·배터리나 최종 선명도의 근거가 아니다. 특히 3D 사진 촬영은 별도 렌더러를 사용하므로 실제 JPEG 생성 결과도 확인한다.

증거 경로는 `qa/living-completion-2026-11-01/desktop`, `mobile`, `desktop-diagnostic`의 `living-completion.json`과 PNG다. 게시판 컴퓨터 증거는 `desktop-diagnostic`에 있다. **도서관 최종 통과 증거는 `desktop-library-final`과 `mobile-library-verified`에 있다.** 이 실행들에서 페이지 런타임 오류·실패 응답은 없었다. 개별 통과 행은 가로 넘침 검사도 통과했다. 초기의 도서관 실패 JSON은 삭제하지 않고 아래 원인과 함께 보존했다.

### 도서관 QA 대기 조건 수정

첫 두 실행에서 배달 직전 이동이 멈췄다. 실제 충돌·입력 진단을 추가한 결과, QA는 모델이 `carrying`으로 먼저 바뀐 뒤 `dialog.close()`의 비동기 close 이벤트가 집기 애니메이션을 시작하기 전 `busy:false` 순간을 지나갔다. 그 상태에서 누른 이동 입력이 곧 시작된 집기 잠금에 의해 정상적으로 비워졌고, QA는 키/터치를 다시 누르지 않은 채 기다렸다.

`desktop-diagnostic/approach-east-probe.json`에는 실제 충돌 모델에서 `canMove:true`, 책 8방향 모두 통과, 가로막는 원·장애물 없음, `gameLocked:false`이지만 집기 중 실제 `input.locked:true`인 시점이 기록되어 있다. 집기가 끝나면 입력 잠금은 정상 해제되었다. 따라서 이 실패를 접근 반경이나 배달 위치의 제품 결함으로 분류하지 않는다. 테스트를 집기의 `busy:true` 시작 → `busy:false`와 실제 입력 잠금 해제 순서로 기다리도록 고쳤다. 게임 시간이나 보상을 바꾸지 않았다.

휴대폰 카메라 방향으로 계산한 별도 시작점 `(-6.258, 3.704)`은 집기가 끝난 자세의 책을 아르마딜로 책장 안에 배치했다. `mobile-library-final/approach-east-probe.json`에서 `canMove:true`이지만 `canCarry:false`, 해당 collider `(world x:10.15, z:7.6)`를 확인했다. 실제 걷기로 들어갈 수 없는 QA 순간이동 위치였으므로 이것도 제품의 통행 차단으로 분류하지 않는다. QA setup을 몸과 책 모두 충돌하지 않는 원 밖 위치로 고르도록 변경했고, 마지막 접근·선택·배달은 여전히 실제 터치로 수행한다. 거부된 QA 시작점은 `approach-*-setup.json`에 남긴다.

최종적으로 추가 대상 5개 흐름은 두 규격에서 모두 완료했다. 이 감사에서 새 제품 P0/P1을 확인하지 않았다. 이는 다른 의뢰 3건, 모든 카페 주문, 모든 사진 배경·동행 조합, 실제 휴대폰 하드웨어까지 완주했다는 뜻은 아니다. 배포 판정은 이 대표 완료 흐름과 별도의 전수 진입·반응형·저장·교통 왕복 결과를 함께 사용한다.
