## 확인 후 해소된 후보

`openMapWorkshop`의 초기 검토 소스는 현재 정답인 항목 수만 세어 이미 본 네 관찰 중 하나에서 다시 오답을 고르면 `살펴본 발견 4 / 4`가 3 / 4로 감소할 수 있었다. 구현 담당자가 독립적으로 같은 문제를 발견해 13:30 UTC경 `states[].reviewed`를 추가했다.

수정된 실제 모듈을 Chromium에서 import하고 실제 DOM에 mount하여 다음 순서만 재현했다.

1. equator=0, south=1, ocean=1, limits=2를 선택해 네 설명을 모두 본다.
2. equator로 돌아가 오답 1을 선택한다.
3. 정리 함수를 호출한다.

관측 결과는 `before: 살펴본 발견 4 / 4`, `after: 살펴본 발견 4 / 4`이고 오답 재관찰 피드백도 정상이다. 현재 소스의 `reviewed`는 정답을 한 번 본 사실을 보존하며 현재 선택/피드백과 분리된다. **현재 결함으로 남기지 않는다.** 구현 담당자의 터치 스크립트에도 같은 회귀가 추가됐다.

## 화면 증거와 한계

`qa/task2-classroom-2026-11-01/browser-review.json`은 1440×900, 390×844, 844×390, 768×1024, 1024×768 각각에서 언어 진도 왕복, 이야기 세 개 완성, 지도 네 관찰과 가로 넘침 없음의 시나리오 결과를 기록한다. 이 리뷰에서는 390×844 지도, 844×390 이야기, 768×1024 영어 캡처를 직접 열어 읽기/배치/닫기 위치를 확인했다. 작은 화면은 모달 스크롤로 이어지는 구성이고, 지도는 좁은 화면에서 질문 위에 배치된다. 모델/최소 DOM 검사로 레이아웃 통과를 주장하지 않는다.

다만 위 JSON에는 작업 중 발생한 `amusement/bumper-play.css` 404와 그 console error 한 건이 남아 있어 실행 전체가 깨끗하게 통과한 증거는 아니다. 해당 파일은 현재 존재하지만, 오류가 없는 새 로드 확인 결과를 통합 담당자가 남겨야 한다. Task 2 scoped 코드 결함으로 분류하지 않는다.

검토 종료 시점에 실제 앱의 터치 요리 브라우저 실행은 구현 담당자가 진행 중이었다. 따라서 휴대폰/태블릿 요리 완료, 길어진 결과 문구, 닫고 초안 복원 및 팬케이크 뒤집기 조작의 최종 기기 판정은 그 결과와 별도 통합 검증을 따른다. 실물 모바일 GPU, iOS Safari, 음성의 청취 품질은 검증하지 않았다.

## 후속 독립 확인 · 요리 프레임 중복 그리기 제거

구현 담당자의 요청에 따라 `dist/home/cooking-controller.js`와 `tests/cooking-observations.test.mjs`의 마지막 추가 변경을 독립적으로 읽었다. **사양·품질 PASS 유지, 새 P0/P1/P2 없음.** 새 브라우저나 전체 테스트 재실행은 하지 않았다.

`render(s,{paint=true})`는 기존 DOM/세션 상태 갱신을 유지하고 viewport 그리기만 선택적으로 생략한다. `apply(TICK)`에서만 `paint:false`를 전달하므로 가열 프레임은 상태 update → 애니메이션 tick → viewport render 순서로 한 번 그려진다. `tick`의 마지막 그리기는 상태 변화가 없는 정지 프레임에도 유지된다. mount, 버튼, blur/visibility pause, 렌더 실패 처리 등 다른 `render(s)` 호출은 기본값으로 즉시 그린다. reducer 시간 처리와 0.5초 저장 checkpoint, 저장 초안의 paused 구조는 변경하지 않았다.

추가 회귀는 단순 호출 개수 외에도 복원 mount와 resume/pause의 즉시 그리기, 가열 중 UI 시간/모델 시간 증가, 매 0.5초 저장 및 저장본 running=false, 정지 프레임의 무가열을 함께 확인한다. 실제 controller에 주입한 session/viewport 호출 순서를 검사하므로 이 변경 목적에 적절하다. 구현 담당자의 수정 전 `update→render→tick→render` 실패, 수정 후 요리 10/10 및 관련 합계 20/20 통과 증거를 사용한다. 실제 GPU 성능 향상이나 실물 기기 성능 통과로 해석하지 않는다. actual tap 코코아/팬케이크의 최종 결과는 여전히 구현 담당자의 진행 중 QA를 따른다.
