# 이동·쉬는 놀이·하늘·날씨 검수 · 2026-11-06

이번에는 이전 출시 기록에 남았던 **건너뛰지 않은 비행·항해, 시소 친구 합류, 미끄럼틀 전체 흐름, 공통 하늘과 날씨**를 실제 입력부터 결과·복귀까지 확인했다. 핵심 가치 기준은 힐링·휴식·즐거움이다. 이동은 조종 게임처럼 소개하지 않고 느긋하게 풍경을 보거나 곧바로 도착하는 선택으로 유지했다.

## 개선

- 배의 상태 live region이 같은 문장을 매 프레임 교체하지 않는다. 일시정지 중 ‘바로 도착하기’를 누르면 ‘계속하기를 누르면 마무리해요’라고 알려 정지와 도착 예약의 차이를 설명한다. 작은 화면에서도 안내를 한 줄 말줄임으로 잘라내지 않는다.
- 한글 조합 키는 배의 종료 단축키로 처리하지 않는다. 비활성/숨김/중복 클릭을 무시하며, 조작판 제거 뒤 연결된 행동 버튼 또는 장면으로 키보드 초점을 돌린다. 지도 예약 뒤에는 실제 새 지도 안의 버튼 포커스가 유지됨을 확인했다.
- 비행 조작판의 상태문 12px·버튼 13px을 각각 14px로 키웠다. 안전 영역은 실제 조작판의 크기를 읽는 기존 카메라 계약을 유지한다. 폰 세로/가로, 태블릿 세로/가로, 컴퓨터 5규격에서 14px 적용과 48px 이상 버튼, 화면 안 배치, 도름이 가시성을 확인했다.

초기 귀환 검사는 QA가 지도에 없는 독립 공항 항목을 찾는 오류였고, 실제 지도에 있는 놀이섬을 선택한 뒤 실제 공항 버튼으로 진행해 통과했다. 하늘 QA의 선택자도 상태 속성을 가진 div와 select를 함께 찾았던 것이므로 `select[data-sky-mode]`로 좁혔다. 이 두 건을 제품 결함이나 제품 수정으로 세지 않는다.

## 회귀·독립 검토

`node --test tests/boat-controls-accessibility.test.mjs`: 새 3개 검사 모두 수정 전 실패 → 수정 후 통과. 같은 상태의 live region 쓰기 억제, 도착 예약 안내, 조합 키·비활성/제거된 버튼, 하선 후 초점 복귀를 검사한다. 실제 스크린리더 청취와는 구분한다.

체육 담당의 별도 코드 리뷰에서 차단 문제를 찾지 않았으며 지도 초점의 실제 검증을 요청했고, 후속 실제 흐름에서 `mapFocus.inDialog=true`로 확인했다. 반대로 교통 담당이 검토한 체육 변경의 독립 리뷰는 [체육 교차 검토](journey-cross-review-sports-2026-11-06.md)에 기록했다.

## 재현·한계

로컬 서버에서 `QA_FILTER=boat-full-outbound,boat-full-return node scripts/journey-quality-browser.mjs`와 해당 스크립트의 다른 시나리오 이름으로 선택 실행한다. `QA_OUT`으로 별도 결과 디렉터리를 지정한다. 테스트용 브리지는 유효한 근접 위치 준비와 읽기, 그리기 샘플링만 하며 점수·완료 상태·시계·주행 시간을 조작하지 않는다. 지도, 탑승·출발·멈춤·하차는 실제 UI 입력이다.

Chromium의 390×844 터치 에뮬레이션, SwiftShader, DPR .35, 12프레임마다 그리기 환경이다. 스크린샷 시에는 연속 그리기로 돌아오지만 DPR은 낮다. 따라서 실제 폰/iPad/Safari의 FPS, 배터리, 촉감, 보조공학 음성을 검증했다고 말하지 않는다. 날씨의 상업 이용 조건은 [상업 준비 검토](commercial-readiness-2026-11-06.md)에서 별도로 다룬다.
