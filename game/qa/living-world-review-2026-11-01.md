# 생활·야외 공간 출시 검토

검토일: 2026-11-01. 상용 제품 비교 기준은 [market-benchmark-2026-11-01.md](market-benchmark-2026-11-01.md)를 사용했다. 이번 검토에서 상용 게임을 직접 플레이하지 않았으며, 비교는 공식 자료 기반이다.

범위: `dist/village`, `fishing`, `gathering`, `produce`, `plaza`, `square`, `marshmallow`, `gym`, `aviation`, `transport`, `observatory`, `weather`. 관련 생활 기능 누락을 막기 위해 `bakery`의 포장·2층 카페·차 한잔과 운동장 실제 공놀이 5종, 놀이터 3종도 포함했다. 교실·집의 일반 학습 도구 및 놀이공원은 다른 담당자의 검토 범위다. 도서관은 교실 담당자가 책·대출·찾기 의뢰를 전수 검토했음을 확인했다.

**증거 수준:** 아래 inventory는 현행 컨트롤러·모델·문구·저장 연결을 읽은 소스 감사다. `source-inventory.json`에는 12개 공간, 정적 진입점 71개, 동적 카페 진입점 2개와 하위 도구를 기록했다. 반복 좌석·같은 종류의 채집 지점은 같은 행에 묶었다. 기능이 선언되어 있다는 것과 실제 기기에서 완료했다는 것을 구분한다. 이 문서만으로 모든 활동의 모바일·태블릿·컴퓨터 완료를 주장하지 않는다.

## 핵심 판단

기능이 모두 빈 모달 수준인 것은 아니다. 낚시·패스·던지기·야구·카페·체육관 등에는 실제 입력, 진행 상태, 결과, 쉬기, 복귀가 있다. 광장 체조·운동 기구에는 자동/직접 모드가 나뉘며, 배와 비행기는 움직임 없는 이동을 제공한다. 이미 있는 구조를 유지하면서 첫 행동과 다음 행동이 끊기는 부분을 고치는 것이 우선이다.

확인한 가장 명확한 P1은 **텃밭에서 물을 준 뒤 ‘수확할 수 있어요’라는 안내와 disabled 버튼이 충돌하는 것**이었다. 완료 상태가 같은 패널의 다음 행동을 막았으며, 이 검토 중 수정했다. 다른 명확한 부족함은 축구 공의 고정된 단발 연출, 후속 용도가 없는 일부 채소, 짧고 제한된 편지 내용이다. 이들은 대형 새 시스템을 추가할 이유보다는 현재 기능의 목적과 안내를 정확히 해야 하는 이유다.

## 우선순위와 구체 근거

### P0

소스 검토에서 새 출시 차단 오류를 확정하지 않았다. 이는 P0가 없다는 보증이 아니다. 자동 이동의 도착·반환, 모바일 전체 완료, 태블릿 터치 연속 조작, 저장 실패/백그라운드 복귀는 전체 통합 검증 결과를 함께 봐야 한다.

### P1 — 텃밭 다음 행동 불가 (수정됨)

- 재현 경로: 공원 작물 열기 → 해당 놀이 계절 → 물 주기 완료.
- 수정 전 `dist/produce/controller.js`는 `phase='done'`으로 전이하지만 `start()`·`setSeason()`·`snapshot().canStart`는 `phase==='idle'`만 허용했다.
- 수정 전 `dist/produce/game-integration.js`는 ‘직접 수확할 수 있어요’ 상태와 disabled ‘돌보기를 마쳤어요’ 버튼을 함께 보여 주었다.
- 결과: 같은 작물에 물을 주고 수확하려면 패널을 닫고 다시 상호작용해야 했으며, 패널은 이 조건을 안내하지 않았다. 사용자는 완료 버튼이 고장났다고 이해할 수 있었다.
- 수정 범위: 완료/실패 후 명시적 다음 행동을 허용하되 새 행동 전에 이전 시각 세션을 복구하고 elapsed·attempted·committed를 초기화한다. 동작 중 재시작은 막고 실제 작물 상태를 기준으로 다음 행동을 정한다. 저장 실패·취소·중복 수확 회귀를 확인한다.
- **검증·수정 상태는 아래 최신 증거 절에 기록한다.**

### P2 — 출시 문구·사용 목적 개선 후보

1. **축구의 깊이와 이름 — 문구 반영됨:** `dist/world/school-builders.js`의 `kickBall()`은 고정 경로 단발 연출이다. 검토 후 `dist/world/school.js`의 `sportsField.ball` 이름을 ‘골대로 공 굴려 보기’로, `dist/school/tools.js` 안내를 ‘톡! 공을 골대 쪽으로 굴려 봤어요’로 고쳤다. 새 게임 구현 없이 실제 기능의 기대를 맞췄다.
2. **채소의 후속 용도:** `state/food-catalog.js`에 토마토·호박·잎채소 소비처가 없다. 수확은 가능하지만 반복 필요성은 낮다. 새 저장 스키마/요리를 이번 출시 조건으로 강제하지 말고, 재료 설명을 실제 사용 범위에 맞춘다.
3. **요리 일지의 정확성 — 문구 반영됨:** `state/progress.js`의 `COOK_FISH`가 `home-cook`를 기록하지만 최초 `world/activities.js`의 글은 과일과 요거트를 특정했다. 검토 후 ‘고른 재료로 요리를 만들고 나만의 한 그릇을 완성했다’로 바꿔 연결 활동에 맞췄다.
4. **우체국 재방문:** 9개의 편지 슬롯과 친구별 동일한 답장으로 한정된다. 무한 편지·랜덤 보상보다 전한 마음별로 어울리는 짧은 답장을 보완하는 편이 역할놀이 가치에 맞는다.
5. **장황한 구현 중심 안내:** 체육관 설명의 ‘원래 도름이’, ‘실제로 닿은’, ‘기존’ 표현은 내부 검증의 흔적이다. 기본 도움말은 조작과 다음 행동만 남기고 세부 설명은 펼쳐 보기로 정리할 수 있다.

## 휴대폰·태블릿·컴퓨터 공통 활용성

- 소스상 낚시·마시멜로·공놀이·체육관은 버튼과 키보드를 제공하고, hold가 필요한 일부 도구는 toggle/자동 대안도 있다. 태블릿은 단순히 큰 휴대폰이라고 간주하지 말고 768–820px 세로 및 가로 모드에서 실제 터치를 확인해야 한다.
- 카페·체육관·요리·공방은 화면 높이에 맞는 내부 스크롤과 가로 배치를 구현했다. 구현 존재가 클릭 가능성을 보증하지 않으므로 결과와 조작부가 겹치는지 실제 캡처로 확인한다.
- 천문·날씨·사진관은 정보 밀도가 높다. 글자 확대, 네이티브 select, 세로 스크롤, 닫기 버튼을 함께 확인한다. 음향이 없어도 상태를 알 수 있는지가 중요하다.
- 여행·기구·풍경은 동작 줄이기·바로 도착·언제든 종료가 핵심이다. 소프트웨어 렌더러의 느린 프레임을 실기기 성능 수치처럼 보고하지 않는다.
- 카페 2층 음식/친구 초대처럼 장소·층·좌석 조건이 있는 기능은 단순 모달 열기 테스트로 완료 처리하지 않는다. 직접 이동과 결과 소비를 따로 검증해야 한다.

## 최신 증거 및 남은 검증

- `qa/living-world-review-2026-11-01/source-inventory.json`: 현행 소스 진입점 목록.
- `tests/produce-continuation.test.mjs`: 실제 controller와 progress reducer를 사용한 신규 회귀. 수정 전 4개 중 3개 실패로 완료 후 다음 행동/계절 선택 문제를 재현했고, 수정 후 4개 모두 통과했다. 같은 패널의 다음 돌봄, 접촉 전/후 취소, 저장 거절 후 재시도, 중복 수확, 계절·읽기전용 보호를 확인한다.
- `produce-before/produce.json`과 `water-completed.png`: 새 휴대폰 브라우저에서 실제 물주기 완료 뒤 `ready:true`, `canStart:false`, disabled ‘돌보기를 마쳤어요’를 재현했다. 당시 다른 담당자의 변경 중 `amusement/bumper-play.css` 404가 한 건 있었으며 텃밭 오류와 무관했다.
- `produce-after-phone/produce.json`, `produce-after-tablet/produce.json`, `produce-after-desktop/produce.json`과 각 두 PNG: 각각 새 390×844 터치 / 820×1180 터치 / 1280×900 클릭 환경에서 계절 선택 → 물주기 → 활성 ‘호박 2개 수확하기’ → 실제 2개 수확 → 활성 ‘다시 물 주기’ → 산책 복귀를 확인했다. 세 규격 모두 스크립트 오류·콘솔 오류·실패 응답·가로 넘침 없음. 결과·다음 행동·계절 선택·복귀가 화면에 보이는 것도 PNG로 확인했다.
- 텃밭 브라우저 검증은 이동만 QA 진입 훅을 사용했고, 실제 입력·애니메이션·저장 reducer를 사용했다. 성장 상태/시간/보상은 조작하지 않았다. 렌더러 비용을 줄이기 위해 DPR 0.35를 사용했으므로 캡처는 배치·동작 증거이며 최종 그래픽 선명도나 실제 기기 성능의 근거가 아니다. CSS viewport 크기는 그대로이며, 수정 후 PNG는 CSS 크기로 저장했다.
- 이 문서의 직접 브라우저 완료 검증 범위는 위 텃밭 시나리오다. 다른 활동은 소스 감사와 입장 증거만으로 모든 활동의 완료 통과를 주장하지 않는다.
