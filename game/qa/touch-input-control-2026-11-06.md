# 그림 다음 첫 터치의 대조 실험

미술 저장 검사 중 touch/pointer down·up은 도착하지만 브라우저가 click을 만들지 않는 실행을 발견했다. 이 현상을 저장 보호 코드의 실패로 단정하거나 제품에 추가 클릭 처리로 덮지 않고, **앱 코드가 전혀 없는 HTML**에서 분리했다.

설치된 Chromium은 `154.0.8037.57`, Playwright는 `1.56.1`이다. 호환 번들 설치 요청은 실행 환경에서 403으로 차단됐다. 다른 다운로드 경로로 우회하지 않았다. 버전 차이가 있다는 사실만으로 원인을 확정하지 않는다.

## 대조와 결과

화면은 390×844, DPR 1이며 canvas와 표준 button만 있다. 저장소·모달·앱 포인터 핸들러·스크롤 호출이 없다. CDP touch를 보내고 브라우저의 trusted click과 실제 카운터 증가를 검사한다. 합성 DOM click이나 재시도 성공을 첫 터치 성공으로 세지 않는다.

| 입력 조건 | 첫 터치 성공 |
| --- | ---: |
| 선 긋기 없이 버튼만 누르기 | 12/12 |
| 한 번의 즉시 이동으로 획을 그린 뒤 누르기 | 0/12 |
| 같은 즉시 획 다음 500ms 기다리기 | 0/12 |
| 같은 즉시 획 다음 native tap gesture | 0/12 |
| 10개 이동 샘플을 20ms 간격으로 보내기 | 0/12 |
| 시간 간격이 있는 획 + 버튼을 80ms 누르기 | 0/12 |
| 시간 간격이 있는 획 + 다음 터치 전 600ms + 80ms 누르기 | 12/12 |
| 시간 간격이 있는 획 + 다음 터치 전 600ms, 누르기 대기 없음 | 12/12 |
| 즉시 획 + 다음 터치 전 600ms + 80ms 누르기 | 0/12 |

Playwright 기본 실행 플래그 없이 고유 임시 프로필과 localhost CDP로 시작한 같은 Chromium에서도 처음 네 조건의 결과는 각각 12/12, 0/12, 0/12, 0/12였다. 따라서 기본 실행 플래그만의 원인이라는 가설은 지지되지 않았다.

**입력 샘플의 시간 간격과 다음 터치까지의 간격을 함께 둔 조합**은 이 환경에서 재현 가능한 성공 조건이다. 특정 Chromium 결함의 원인을 확정하거나 모든 빠른 입력·실물 기기를 합격시키는 근거는 아니다. 제품 이벤트 코드는 이 대조를 위해 수정하지 않았다.

실제 미술 DOM에서도 같은 조합으로 최초 저장과 추가 획 뒤 첫 저장 **12/12**가 성공했고, 재터치·Enter 대체 입력은 0회였다. 전체 3D 게임의 정상 저장·지연 복원 후 반복 저장은 [학습 검수](learning-delight-review-2026-11-06.md)의 후속 실행 결과를 따른다.

## 재현

```sh
QA_TOUCH_MODE=stroke-direct QA_STROKE_STEPS=10 QA_STROKE_INTERVAL=20 \
QA_TAP_DELAY=600 QA_TAP_HOLD=80 QA_OUT=qa/touch-control-repeat \
node scripts/touch-gesture-diagnostic.mjs
```

간격 관련 환경변수를 생략하면 원래의 즉시 획 대조다. 기본 실행은 네 모드를 각각 12회 비교한다. `QA_TAP_DEFAULTS`와 `QA_UNIQUE_TOUCH_IDS`는 좌표 외 접촉 필드·식별자를 분리하는 선택 진단이다.

[압축 결과](touch-input-control-summary-2026-11-06.json)는 모든 회차의 첫 터치 판정과 실제 click 수, 획 종료부터 버튼 입력까지의 간격을 남긴다. 상세 이벤트 로그와 PNG를 포함한 로컬 `qa/` 실행 폴더는 모두 저장소에 포함하지 않으며, 위 스크립트로 다시 생성할 수 있다.
