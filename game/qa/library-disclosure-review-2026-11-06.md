# 도서관 안내 접기와 시야 확보 · 2026-11-06 KST

기존 도서관 가로 검수가 버튼 간 겹침만 확인하고 실제 책장과 도름이의 가림을 충분히 평가하지 못했다. 이 후속 작업은 안내를 선택적으로 접어 놀이 시야를 돌려주는 데 초점을 맞췄다. 내용·정답·저장 모델·카메라는 바꾸지 않았다.

## 제품 변경

- 항상 남는 얇은 막대에 의뢰 번호와 진행, 안내 펼치기/접기, 다시 읽기, 그만하기를 둔다. 완료하면 근거 보기와 다음 의뢰/마치기, 저장 실패면 미저장 상태와 저장 재시도가 남는다.
- 긴 제목·단서·운반 목적지만 `quest-details`에 접는다. `aria-expanded`와 `aria-controls`가 맞으며 접기는 종료 동작이 아니다. 입력 잠금이나 의뢰 진행을 바꾸지 않는다.
- 작은 가로 화면에서는 처음에 접혀 있다. 한 번 펼치거나 접으면 같은 활동의 회전·다음 의뢰에서도 선택이 유지된다. 새 활동은 화면에 맞는 기본값을 쓴다.
- 568px 가로에서는 보이는 라벨만 안내/읽기/근거/다음/그만/재시도로 줄이고 전체 의미는 `aria-label`로 제공한다. 모든 도구 버튼은 최소 48×48px다.
- 접힌 상태의 완료는 `role=status` 및 `aria-live=polite` 진행 표시로 알린다. 같은 위치를 덮던 중복 완료 토스트만 생략했다. 오답 이유 대화상자와 저장 실패 안내·재시도는 유지한다.

수정 소유 파일은 `dist/library/quest-controller.js`, `dist/library/quest.css`, `dist/index.html`의 library-quest 블록이다. 회귀 3개를 `tests/library-quest-disclosure.test.mjs`에 추가했고 기존 reach 테스트의 가짜 DOM에 새 속성 API만 보완했다. 공용 CSS·카메라는 수정하지 않았다.

## 정상 해상도에서 직접 확인

DPR 1 브라우저 캡처를 열어 책장·친구·도름이와 실제 행동 후보가 보이는지 확인했다. 렌더링은 12프레임마다 샘플링하지만 캡처 직전에는 그리기를 복원하며 활동 시간을 빠르게 하지 않는다.

| --- | --- | --- | --- |
| 844×390 | 약 276×66px | 약 361×66px | 읽기·운반·완료·근거·다음 의뢰·그만하기 |
| 667×375 | 약 276×66px | 약 361×66px | 읽기·운반·완료·근거·다음 의뢰·그만하기 |

각 흐름에서 안내 펼치기→회전 후 선택 유지→접기→단서 다시 읽기→책장 원문 읽기→손에 들고 터치 이동→전달→완료를 실행했다. 완료 시 버튼이 한 줄을 유지하고 모든 실제 하단 버튼과 겹치지 않는다. 종료 뒤 의뢰와 입력 잠금이 해제된다. 확대된 안내는 사용자가 선택할 때만 나타나며 다시 접는 버튼이 남는다.

저장 실패 검수는 책을 실제로 읽고 운반한 뒤 저장/백업 키의 쓰기만 QuotaExceededError를 내도록 격리했다. 보상·완료 상태는 주입하지 않았다. 실패 중 재시도는 의뢰를 전진시키지 않았고, 원래 저장 API로 복구한 뒤 같은 실제 버튼을 눌러 도장을 저장했다. 전역의 빨간 저장 실패 안내도 보이는 상태였다.

## 검수 한계와 QA 보정

실물 기기·Safari·스크린리더 실사용은 검증하지 않았다. 근처 위치 준비를 사용하므로 지도 입구부터의 전체 보행 경로를 증명하는 자료는 아니다. 저장 부족은 통제된 실패 fixture다. 큰 가로 세 규격은 좁은 라벨 분기를 추가하기 직전에 완료했으며 해당 규격의 문구·배치는 그대로다.

저장 복구 직후 첫 QA는 눌린 버튼의 `translateY(2px)` 피드백을 줄바꿈으로 오인했다. 원래 0px 일치 비교를 실제 기존 눌림 효과 2px를 허용하도록 보정한 뒤 최종 실행을 통과했다. 제품을 바꿔 검수에 맞춘 사례가 아니다.
