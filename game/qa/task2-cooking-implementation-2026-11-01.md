# Task 2 요리 실험실 내용·관찰 일치 수정

검토일: 2026-11-01. 계획: `docs/superpowers/plans/2026-11-01-dorms-release.md` Task 2.

## 범위

- 제품 변경: `dist/home/cooking-model.js`, `dist/home/cooking-controller.js`.
- 회귀 추가: `tests/cooking-observations.test.mjs`.
- `cooking-view.js`는 읽고 실제 Three.js 세션 테스트에서 사용했으나 수정하지 않았다.
- 공유 게임/HUD/UI, 저장 스키마, 자산, 다른 활동은 수정하지 않았다. 커밋·푸시는 수행하지 않았다.

## 확인한 문제와 수정

1. 기존 코코아는 7바퀴를 넘겨 저으면 `촘촘한 포근한 코코아`/`dense`로 바뀌고 섞임 점수가 떨어졌다. 코코아는 충분히 섞은 뒤 추가로 저어도 동일한 섞임을 유지한다. 샐러드와 팬케이크의 과혼합 표현은 유지한다.
2. 기존 모든 레시피는 첫 번째 재료부터 넣으면 고르게 퍼졌다고 설명하고, 다른 순서는 15점을 감점했다. 이제 첫 재료를 사실대로 기록하고 이 모형은 순서의 영향을 계산하지 않는다고 설명한다. 순서만 바꾼 실험에는 임의의 차이를 만들지 않는다.
3. 기존 비율 설명은 두 번째 재료와 첫 번째 재료의 비만 보고 묽거나 되직하다고 단정했다. 이제 기준 비율과 비교해 가장 차이가 큰 재료의 실제 비중을 설명한다. 섞기 점수는 섞는 횟수만 평가하며 재료 비율이나 순서 때문에 감점하지 않는다. 화면의 점수 이름도 `고르게 섞임`에서 `섞기 기준 (게임 모형)`으로 맞췄다.
4. 코코아의 실제 화면 색은 코코아의 비중으로 결정되지만 안내와 결과는 가열 중 색이 변한다고 주장했다. 이제 코코아는 쌓인 열과 모형 목표 18칸을 비교하도록 안내하고, 가열에 따른 색 변화는 계산하지 않는다고 결과에서 설명한다. 약하게 18초와 중간으로 9초라는 기존 비교 활동을 유지한다.
5. 팬케이크는 계속 가열에 따른 색을 관찰한다. 색과 결과 문구가 같은 열 구간을 사용하도록 맞췄다. 뒤집기 결과는 실제로 기록한 전후 열의 양을 설명하고, 구현하지 않은 양면 색 차이를 관찰했다고 말하지 않는다.
6. 레시피 안내에서 첫 재료를 반드시 특정 재료로 시작해야 하는 듯한 표현을 제거했다. 도움말·섞기 안내 역시 변경한 모형과 맞췄다.
7. 브라우저 검수 중 느린 가열을 소스에서 진단하며, 가열 TICK마다 요리 뷰를 두 번 그리는 경로를 발견했다. 부모의 추가 배정에 따라 TICK은 UI와 세션 상태를 갱신한 뒤 애니메이션 tick 다음에 한 번만 그리도록 수정했다. 최초 표시, 버튼 조작, 일시정지·재개는 계속 즉시 그린다. `game.js`의 전역 시간 처리와 요리의 저장 주기는 변경하지 않았다.

## 먼저 실패를 재현한 기록

제품 수정 전에 아래 명령으로 최초 6개 회귀를 실행했다.

```sh
node --test tests/cooking-observations.test.mjs
```

결과: **6개 중 4개 실패, 2개 통과**.

| 회귀 | 기존 동작으로 발생한 실패 |
|---|---|
| 충분히 섞은 코코아를 더 젓기 | 8바퀴에서 실제 `dense`, 기대 `soft` |
| 재료 순서만 뒤집기 | 샐러드의 실제 85점, 동일 비율·횟수의 정방향 100점 |
| 코코아 열 결과 | 실제 `옅은 변화`, 색/변화가 아닌 열의 양 설명을 기대 |
| 실제 컨트롤러 가열 안내 | 실제 `변하는 색을 보고 꺼낼 때를 골라요`, 코코아의 쌓인 열 안내를 기대 |

기존 샐러드/팬케이크 반응 및 v1 저장 복원, 실제 Three.js 요리 뷰의 코코아 색과 빌린 캐릭터 복원 검사는 이 단계에서도 통과했다.

## 수정 후 검증

최종 명령:

```sh
node --test tests/cooking-observations.test.mjs
node --check dist/home/cooking-model.js
node --check dist/home/cooking-controller.js
```

결과: **10개 테스트 모두 통과**, 두 모듈 문법 검사 통과.

- 코코아 8·16·30바퀴에서 섞임 유지.
- 세 레시피 모두 순서만 바꿨을 때 섞기 점수 유지 및 실제 첫 재료 기록.
- 코코아의 적은 열·목표 부근·많은 열 구분과 일정한 재료 색.
- DOM 대역에 실제 컨트롤러를 올려 코코아/팬케이크의 가열 안내 확인.
- 코코아 약하게 18초와 중간으로 9초의 동일한 누적 열·결과 확인.
- 요거트 비중을 바꾼 샐러드가 실제 재료 비중을 설명하고 섞기 점수에 무관한 감점을 하지 않는지 확인.
- 팬케이크의 세 가지 가열 색·뒤집기 전후 기록 설명 확인.
- 기존 샐러드/팬케이크 과혼합 반응 유지, v1 초안·직전 결과 저장 검증과 가열 이어하기 확인.
- 실제 Three.js 요리 세션에서 코코아 표시색, 평평한 음료 모형, 닫기 후 캐릭터 부모·위치 복원을 확인.
- 가열 프레임마다 `세션 update → 세션 tick → viewport render`가 정확히 한 번씩 실행되는지 확인. 최초 표시와 일시정지·재개 버튼은 즉시 렌더되고, 매 0.5초 저장과 멈춘 상태의 비가열도 유지한다.

추가 렌더 회귀는 수정 전에 실제 controller 이벤트가 `update → render → tick → render`여서 실패했다(10개 중 9개 통과, 1개 실패). 중복 제거 후 같은 검사를 다시 실행하여 10개 전부 통과했다.

## 느린 가열 진단 근거

- `game.js:frame`은 프레임 간 시간을 `Math.min(ms/1000, .045)`로 제한해 `homeTools.tick`에 전달한다. 기존 요리의 시간도 이 시뮬레이션 시간으로 누적된다. 본 작업에서 전역 시간 제한을 변경하지 않았다.
- 실제 모델을 60초 분량의 가상 프레임으로 호출한 결과: 1fps는 요리 2.7초/열 5.4칸, 2fps는 5.4초/10.8칸, 3fps는 8.1초/16.2칸이었다. 따라서 소프트웨어 WebGL에서 계속 가열 중이어도 열 18칸 대기가 실제 60초를 넘길 수 있다. 이는 원리 확인용 Node 실험이며 실제 기기 속도 측정이 아니다.
- 중단 여부는 실시간 `cookingRuntime.running`, `seconds`, `energy`로 구별한다. 저장된 draft의 `running`은 의도적으로 항상 false이므로 실행 상태 판정에 사용하지 않는다.
- 가열 중 `window.blur`, 숨김으로의 `visibilitychange`, 명시적 멈춤/닫기, 45초 자동 종료는 running을 false로 만든다. 다시 열어도 자동 가열하지 않는다.
- WebGL 생성 실패/컨텍스트 손실은 running을 false로 만들고 `renderFailed` 상태에서 후속 조작을 차단한다. 화면의 `cook-render-note` 안내로 구별할 수 있다.
- 지도/하늘 화면, 숨김 문서, 다른 활동의 전용 렌더 경로는 `homeTools.tick` 전에 반환할 수 있다. 일반 요리 모달의 modalLock만으로는 이 tick을 막지 않는다.
- 열 18칸은 코코아의 비교 목표이며 자동 정지점이 아니다. 브라우저 검사의 도달 조건은 실시간 열 `>= 18`을 사용해야 한다.

## 검증 한계와 인계

- 이번 작업의 증거는 새로 실행한 모델·컨트롤러 대역·Three.js 뷰 테스트이다. 실제 브라우저, GPU 렌더링, 터치 조작 및 작은 화면 가독성 검증으로 주장하지 않는다.
- 부모가 전체 브라우저 검수를 담당한다. 확인 권장: 휴대폰에서 길어진 결과 설명과 점수/직전 실험 비교 영역, 코코아의 계량→섞기→가열→완료→한 조건만 바꾸기 흐름, 팬케이크 뒤집기 및 저장 후 가열 재개.
- 실제 요리 온도·조리 안전·영양을 시뮬레이션하지 않는 기존 범위는 유지한다.
