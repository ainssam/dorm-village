## 확인 방식

- 실제 조이스틱·키보드·버튼으로 접근하고 활동을 열었습니다. 방이나 캐릭터 위치를 강제로 바꿔 통과시키지 않았습니다.
- 장소 진입, 활동 시작·종료, 결과까지 진행, 저장 복원은 서로 다른 검수 단계로 구분했습니다.
- 데이터와 사진은 검수용 브라우저에 새로 만들었습니다.
- 모바일 확인은 Chromium의 화면 크기·터치 에뮬레이션입니다. 실제 iPhone/Safari나 Android 기기의 성능을 검증한 결과는 아닙니다.
- 렌더링에는 SwiftShader를 사용했습니다. 이 환경에서 느려진 게임 시간이나 프레임 수를 실제 이용 기기의 성능 문제로 판정하지 않았습니다.

## 자동 검사

- `npm run check`: 작성한 JavaScript 문법 검사
- `npm test`: 포함된 핵심 검사 **190개 통과**
- `npm run test:browser`: **2개 통과**. 실제 MathLive·MathJax·IndexedDB를 사용한 수식 입력 → 미리보기 → 칠판에 올리기 → 저장 → 다시 열기·새로고침 복원 검사. 390×844, 844×390 화면에서 가로 넘침과 고급 수식 펼치기도 확인
- 실제 배포용 HTML·CSS로 차량 나가기 버튼과 스틱의 겹침, 화면 내 배치, 실제 클릭 성공을 검사. 320×568, 390×844, 640×520, 844×390, 1000×800에서 카트·범퍼카 각각 저장 경고 표시 여부까지 **20개 배치 조합** 확인
- 활동 시작 콜백에서 이동 벡터를 지울 수 있는지 회귀 검사 추가

브라우저 검사는 Playwright Chromium이 필요합니다. `npx playwright install chromium` 후 `npm run test:browser`를 실행하거나, 설치된 Chromium 경로를 `CHROMIUM_EXECUTABLE_PATH`로 지정합니다. 기본 `npm test`는 브라우저 설치 없이 실행할 수 있습니다.

## 추가 반영 — 도서관과 활동 완료 흐름

### 도서관: 6개 주제·12권

- 일반 읽기를 3권에서 12권으로 확장했습니다. 나눔·마음·친구·빛·식물·물 책장마다 서로 다른 두 권을 제공합니다.
- 기존 이야기 3권을 보존하고, 사서 의뢰에만 있던 설명문 3권도 일반 읽기에 연결했습니다. 우산 나누기, 비어 있는 지도, 함께 만드는 리듬, 달빛, 씨앗의 이동, 물웅덩이 비교에 관한 짧은 글 6편을 새로 썼습니다.
- 모든 책에 펼쳐 볼 수 있는 질문, 읽은 책 표시, 독서석에서 펼친 권수를 제공합니다. 독서석·대출대·작은 하루 기록까지 연결하며, 저장 구조와 기존 책 ID를 유지했습니다.
- 책장 앞 행동 버튼에 번호와 주제를 표시하고, 긴 글을 읽는 동안에도 책 선택 버튼을 볼 수 있게 했습니다.
- 사서 의뢰는 기존 6권과 4개 임무로 별도 유지합니다. 주제와 원문은 일반 읽기와 같은 자료를 참조해 서로 달라지지 않게 했습니다.

### 추가 검증

- `npm run check` 통과, 핵심 검사 **193개 통과**, Chromium 브라우저 검사 **6개 통과**.
- 새 책 12권 모두 읽기·대출·저장·재로딩, 기존 읽기 저장의 호환성, 사서 의뢰 4개 완주를 모델/저장 검사로 확인했습니다.
- 실제 DOM에서 여섯 책장별 두 권 표시, 질문·선택·대출·읽은 책 표시·새로고침 복원을 검사했습니다.
- 완료 → 다시 하기 / 다음 도전 / 닫기, 다음 단계 진입 후 완료 기록 보존, 블록 실패 후 수정, 좁은 화면 배치를 검사했습니다.
- 실제 Chromium/WebGL 도서관에서 새 책 「두 물웅덩이의 오후」 선택 → 독서석 착석 → 읽기 기록 생성 → 새로고침 복원을 확인했습니다. 실제 주방에서 샐러드 완성 → 결과 화면 → 다시 하기, 다음 레시피 전환 → 방 복귀도 확인했으며 게임 실행 오류는 없었습니다.
- 새 브라우저 검사는 실제 UI·게임 모델·저장 코드를 사용합니다. 집 활동의 3D 뷰포트만 대체해 결과 흐름을 독립적으로 검사하므로 이 검사가 3D 조작감 검증을 뜻하지는 않습니다.
