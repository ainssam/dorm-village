## 확인 방식

- 실제 조이스틱·키보드·버튼으로 접근하고 활동을 열었습니다. 방이나 캐릭터 위치를 강제로 바꿔 통과시키지 않았습니다.
- 장소 진입, 활동 시작·종료, 결과까지 진행, 저장 복원은 서로 다른 검수 단계로 구분했습니다.
- 데이터와 사진은 검수용 브라우저에 새로 만들었습니다.
- 모바일 확인은 Chromium의 화면 크기·터치 에뮬레이션입니다. 실제 iPhone/Safari나 Android 기기의 성능을 검증한 결과는 아닙니다.
- 렌더링에는 SwiftShader를 사용했습니다. 이 환경에서 느려진 게임 시간이나 프레임 수를 실제 이용 기기의 성능 문제로 판정하지 않았습니다.

## 자동 검사

- `npm run check`: 작성한 JavaScript 문법 검사
- `npm test`: 포함된 핵심 검사 **190개 통과**
- `npm run test:browser`: **2개 통과**. 실제 MathLive·MathJax·IndexedDB를 사용한 수식 입력 → 미리보기 → 칠판에 올리기 → 저장 → 다시 열기·새로고침 복원 검사. 390×844, 844×390 화면에서 가로 넘침과 고급 수식 펼치기도 확인
- 실제 배포용 HTML·CSS로 차량 나가기 버튼과 스틱의 겹침, 화면 내 배치, 실제 클릭 성공을 검사. 320×568, 390×844, 640×520, 844×390, 1000×800에서 카트·범퍼카 각각 저장 경고 표시 여부까지 **20개 배치 조합** 확인
- 활동 시작 콜백에서 이동 벡터를 지울 수 있는지 회귀 검사 추가

브라우저 검사는 Playwright Chromium이 필요합니다. `npx playwright install chromium` 후 `npm run test:browser`를 실행하거나, 설치된 Chromium 경로를 `CHROMIUM_EXECUTABLE_PATH`로 지정합니다. 기본 `npm test`는 브라우저 설치 없이 실행할 수 있습니다.

## 남겨 둘 개선 방향

- 도서관의 일반 읽기는 여러 책장에서 같은 세 이야기를 반복합니다. 책장별 주제와 읽을거리를 늘리면 탐색 이유가 더 분명해집니다. 책 찾기 의뢰는 별도 활동이므로 일반 읽기와 구분해 설계하는 편이 좋습니다.
- 기록이 남는 활동과 닫으면 초기화되는 활동이 섞여 있습니다. 현재 안내는 유지하되, 다음 콘텐츠 개편에서는 완료 후 “다시 하기 / 다음 도전 / 방으로 돌아가기”를 일정한 위치에 두는 것이 좋습니다.
- 모든 미니게임의 모든 난이도와 175개 상호작용 지점을 끝까지 완주한 검수는 아닙니다. 같은 형식의 의자·재료 지점까지 전부 정상이라고 확대 해석하면 안 됩니다.
- 공개 배포 후에는 이 코드가 실제로 반영되었는지 확인하고, 실제 휴대폰에서 터치·소리·화면 복귀를 다시 확인해야 합니다.
