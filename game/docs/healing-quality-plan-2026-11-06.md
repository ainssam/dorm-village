## 반복 절차

1. 기존 메뉴별 미완주 목록에서 사용 가치와 위험이 큰 흐름을 선택한다.
2. 실제 입력 → 결과 → 재시도 또는 보관 → 종료·복귀를 확인한다. 문제를 제품/검수 환경으로 구분한다.
3. 사용자에게 의미 있는 수정과 필요한 회귀 검사를 수행한다. 소소한 문구·배치에 구현을 베끼는 테스트를 만들지 않는다.
4. 독립 검토 후 실제 화면과 휴대폰·태블릿·컴퓨터 입력으로 재확인한다.
5. 통합 문법·회귀 검사를 통과한 소스만 GitHub에 현행화하고, 검수한 버전을 Vercel에 배포한다. 배포 후 버전·핵심 자산을 확인한다.
6. 남은 메뉴와 반복 사용 문제로 다음 주기를 이어 간다. 사용자 개입 시 우선순위를 반영한다.

## 이번 첫 주기의 합격 조건

- 휴대폰에서 생활 메뉴가 긴 시점 조작 뒤에 숨지 않는다. 카메라 조작도 찾고 키보드로 사용할 수 있다.
- 쉬기/놀이/배움 선택마다 실제 해당 활동 추천을 보여 주며, 첫 안내가 소개한 경험에 연결된다.
- 작은 하루 기록은 간직한 순간을 먼저 보여 주며 미발견 목록을 숙제로 만들지 않는다.
- 사진첩이 가득 차거나 사진을 지울 때 다음 행동과 보존·취소 범위가 명확하다.
- 그림·수학의 첫 산출물이 읽히고 보관·복귀가 편하다. 기존 저장은 보존한다.
- 선택한 운동 도전과 교통 왕복은 전체 결과까지 실제 입력으로 검증한다.
- 회귀 테스트 수, 실제 브라우저 완료 범위, 시각 검토, 미확인 사항을 구분한다.

실제 이용자의 재미·장기 재방문·지불 의사와 실물 iOS/Android 성능은 자동 검사만으로 보증하지 않는다. 현재 목표는 이 기준에 맞는 제품 경험을 계속 개선하는 것이며 결제 시스템이나 유료 판매 시작을 임의로 추가하지 않는다. 무료 공개와 상업 이용 권한은 별도 조건으로 확인한다.
