# 다음 주기 설계: 수확한 채소로 카페에서 쉬기

작성일: 2026-11-06. **설계 문서이며 현재 공개 후보의 런타임을 변경하지 않는다.** 이번 품질 검토에서 드러난 채소 세 종류의 쓰임 부족을 다음 작업 주기로 연결한다. 구현·기기 검수·저장 마이그레이션이 끝났다는 의미가 아니다.

## 목표와 선택

토마토·호박·잎채소를 수확한 뒤, 기존 밀구름 카페에서 한 그릇을 준비해 앉아서 먹거나 친구에게 건넬 수 있게 한다. 수확의 결과가 짧고 편안한 휴식으로 이어지고 같은 흐름을 다시 즐길 수 있어야 한다. 일회성 장식을 늘려 재고가 쌓이는 시점만 미루는 방식은 이번 해결안으로 삼지 않는다.

**권장 최소안은 사용자에게 하나의 ‘수확 한 그릇’ 경험을 제공하고, 저장 내부에서는 채소별 음식 세 종류를 구분하는 것이다.** 새 교실·제작대·가방·화폐·백엔드를 만들지 않는다. 카페의 기존 주문 위치, 준비와 받기, 음식주머니, 착석, 친구 초대, 접촉 시 음식 소비, 취소·장면 정리 구조를 확장한다.

| 선택 | 효과와 비용 | 판단 |
| --- | --- | --- |
| 공통 음식 ID 1개 + 원재료 선택 | 화면은 단순하지만 어떤 채소를 썼는지 보존할 별도 재료별 제작 장부가 필요하다. 공통 음식 총량과 원재료 장부를 함께 검증해야 한다. | 초기 구현에서는 선택하지 않음 |
| 채소별 내부 ID 3개 + 공통 화면·그릇·준비 흐름 | 기존 `made[음식]`와 `consumed[음식]`를 확장하면 원재료와 완성 음식의 수량을 한 경로로 계산할 수 있다. 외형은 공통 그릇에 내용물만 달라진다. | **권장** |
| 세 채소를 모두 모아 한 접시 | 계절 변경과 세 번의 수확을 사실상 요구한다. 원하는 재료 하나로 쉬러 가기 어렵다. | 제외 |
| 채소마다 집 장식 1개 | 최초 수확의 보상은 생기지만 이후 재고의 쓰임을 해결하지 못한다. | 별도 꾸미기 확장으로만 고려 |

가칭 내부 ID는 `tomatoBowl`, `pumpkinBowl`, `leafyBowl`이다. 제품 화면에서는 ‘수확 한 그릇’ 아래에 토마토·호박·잎채소를 고른다. 준비 후 음식주머니에서는 ‘토마토 한 그릇’처럼 재료를 구분한다. 색만으로 선택을 구별하지 않는다.

## 사용 흐름과 작은 배움

1. **마음에 드는 채소 하나 수확.** 현재 한 번 수확하면 재료 2개를 얻는다. 제철·놀이 계절 선택, 익은 뒤 계절이 바뀌어도 수확 가능한 규칙은 유지한다. 수확 패널 안내는 ‘이 채소 1개로 카페 2층에서 수확 한 그릇을 준비해요’로 연결한다. 없는 재료를 모으라는 과제나 완료 체크리스트는 넣지 않는다.
2. **기존 코알라 자리에서 준비.** 기존 주문 UI에 ‘음료 / 수확 한 그릇’ 선택을 추가한다. 채소 하나와 ‘준비하기 · 재료 1개’를 고르면 그릇 놓기 → 익힌 채소 담기 → 건네기의 짧은 연출을 보여 준다. 약 3~4초는 초기 연출 목표이며 경쟁 타이머가 아니다. 일시정지와 움직임 줄이기를 지원하고 단계마다 반복 클릭을 요구하지 않는다.
3. **명시적으로 주머니에 받기.** 받기 성공 시에만 원재료 1개가 줄고 완성 음식 1그릇이 생긴다. 준비 중 닫기·지도 이동·받기 전 취소는 원재료를 쓰지 않는다. 같은 수확에서 얻은 2개로 두 그릇을 하나씩 준비하면 내 몫과 친구 몫을 마련할 수 있다. 일괄 제작과 주문 수량 조절은 첫 구현에서 제외한다.
4. **혼자 또는 함께 쉬기.** 기존 2층 의자에서 ‘한 그릇 먹기’를 선택한다. 왼쪽 자리에 앉아 기존 친구 초대를 사용하면 ‘친구에게 한 그릇 건네기’도 가능하다. 친구 한 명에게 건네면 음식 1그릇만 소비하고 도름이 몫은 별도 선택한다. 친구가 오는 동안 따로 기다리기를 요구하지 않고 기존 주머니를 사용할 수 있다. 도름이와 친구 모두 **첫 한 입이 입에 닿을 때** 소비한다. 손에 받기나 탁자에 놓기만으로 소비하지 않아, 기존 ‘먹기 전에 취소하면 그대로’ 안내와 일치시킨다.
5. **짧은 반응 뒤 편하게 머물기.** 먹기 뒤 ‘따뜻한 한 그릇을 먹었어요’, 나눔 뒤 ‘친구가 한 그릇을 맛있게 먹었어요’를 보여 준다. 완료 보상·연속 방문·식사 횟수 도장을 추가하지 않는다. 남은 음식은 지금처럼 주머니에 보관하며 같은 일을 다시 할 수 있다.

비용은 **재료 1개 → 음식 1그릇**을 제안한다. 기존 수확량 2개에서 두 사람이 먹을 수 있어, 나눔을 위해 한 번 더 수확하러 가는 마찰을 줄인다. 원재료별 정확한 실물 조리량이나 영양 정보를 뜻하지 않는 게임의 수량이다. UI 단위는 기존 재료 가방의 ‘개’를 유지하며, 임의로 그램·인분·영양 수치를 추가하지 않는다.

배움은 정답을 맞혀야 진행하는 문제가 아니라, 재료 준비 중 또는 받기 완료 후 한 줄로 읽을 수 있는 ‘작은 발견’으로 제한한다. 이를 읽기 위한 새 단계나 필수 버튼을 추가하지 않는다. 긴 설명이 필요할 때에만 접힌 추가 정보를 제공한다. 아래 문구는 초안이며 최종 외형에 실제 보이는 특징과 대조한다.

| 재료 | 초안 | 필요한 시각 근거 |
| --- | --- | --- |
| 토마토 | ‘토마토는 열매예요. 동그란 모양이 작은 조각으로 바뀌었네요.’ | 준비 전 둥근 재료와 그릇 안 조각이 구분됨 |
| 호박 | ‘호박도 열매예요. 껍질과 속의 색을 천천히 비교해 봐요.’ | 준비 전 재료와 익힌 조각의 두 색이 보임 |
| 잎채소 | ‘잎채소는 잎을 먹는 채소예요. 열매와 모양이 어떻게 다른가요?’ | 잎 모양이 둥근 열매·조각과 구분됨 |

친구 반응은 음식별 짧은 세 문장으로 시작할 수 있다. 예: ‘작은 토마토 조각이 알록달록하네’, ‘따뜻한 호박 한 그릇이 포근해’, ‘초록 잎이 작은 정원 같아’. 대답이나 선택을 요구하지 않고 읽지 않아도 진행된다. 이 표현을 건강·영양 효과나 실제 학습 효과의 검증으로 설명하지 않는다.

## 저장 설계와 불변식

현재 `cafeFood`의 상위 구조는 유지한다.

```js
// schema 7 예시: 기존 키/값을 모두 유지하고 새 키만 0으로 추가
cafeFood: {
  packed: { /* 기존 빵 3종 */ },
  made: { /* 기존 음료 7종 */, tomatoBowl: 0, pumpkinBowl: 0, leafyBowl: 0 },
  consumed: { /* 기존 빵·음료 */, tomatoBowl: 0, pumpkinBowl: 0, leafyBowl: 0 }
}
```

별도 `produceConsumed`, 준비 중 예약 재료, 공통 그릇 총수, 친구별 식사 횟수는 저장하지 않는다. 새 variant의 `made`가 해당 채소의 소비 원인이고, `consumed`가 완성 음식의 소비 원인이다.

- `채소 재료 잔량 = 해당 노드의 누적 수확 × 2 − 해당 그릇 made × 1`.
- `완성 음식 잔량 = made − consumed`.
- 모든 수는 안전한 정수이며 0 이상이고 기존 `MAX_FOOD_COUNT` 한도 안이어야 한다. 재료 가방도 전체 root 검증에서 음수를 거절한다.
- 음식별 재료 비용은 schema 7의 고정 계약이다. 누적 `made × 비용`으로 잔량을 계산하므로 출시 뒤 비용을 1에서 2로 바꾸면 과거 소비까지 늘어나 저장이 음수가 될 수 있다. 향후 비용 변경은 별도 마이그레이션 또는 새 recipe ID로 처리하고 단순 상수 수정으로 배포하지 않는다.
- `FOOD_PREPARE_MEAL`은 알려진 ID, `expectedRevision`, `expectedMade`, 현재 재료 1개 이상을 확인한다. 비용·재료명·완성 수량을 호출자가 전달해 바꿀 수 없게 고정 카탈로그로 결정한다.
- 준비 애니메이션은 저장하지 않는다. ‘받기’의 root transaction 성공으로 `made`를 +1하는 한 번의 상태 변경이 원재료 차감과 음식 추가를 동시에 표현한다.
- 먹기·친구 전달은 기존 접촉 시 `FOOD_CONSUME`로 `consumed`만 +1한다. 여기서 원재료를 다시 차감하면 안 된다.
- 위 접촉은 양쪽 모두 첫 한 입의 **입 접촉**이다. 접시에 손이 닿거나 그릇을 넘기는 시점을 새 소비 시점으로 혼용하지 않는다.
- 친구에게 한 그릇을 건넨 것을 도름이의 식사로도 중복 반영하지 않는다. 같은 한 그릇을 동시에 혼자 먹기·친구 전달에 쓸 때는 첫 성공만 반영하고 나머지는 최신 수량을 보여 준다.
- 받기 또는 접촉 전에 취소하면 변화가 없다. 성공 뒤 닫기·장면 이동·새로고침은 이미 확정한 제작 또는 소비를 되돌리지 않는다.
- 저장 실패·두 탭·오래된 revision·장면 교체·좌석 token 변경은 부작용 없이 거절한다. 충돌을 새 revision으로 자동 재주문하지 않는다. 재시도 전에 최신 가방을 보여 주고 사용자가 명시적으로 다시 선택하게 한다.

### 버전 전환

현행 v5/v6는 `exactFoodRecord`로 정확한 음식 키 집합을 검증한다. 현재 목록을 늘린 뒤 그대로 옛 저장에 적용하면 정상적인 기존 저장까지 거절하므로 다음 순서를 지킨다.

1. v5/v6의 빵·음료·consumed 목록을 역사적 상수로 고정한다. 해당 버전은 **옛 목록으로 먼저 검증**하고 새 키가 끼어 있으면 거절한다.
2. 정상적인 옛 상태에만 세 `made`·세 `consumed`의 0을 채워 schema 7로 올린다. 모든 기존 수확·재료·음료·사진·편지·설정·revision을 보존한다. v1~v4의 기존 마이그레이션도 새 초기 `cafeFood`로 수렴한다.
3. `initialProgress`, `validateProgress`, `migrateProgress`, action의 schema 조건, `save.js`의 미래 버전 기준과 업그레이드 목록을 함께 바꾼다. root schema 7에서 새 필드 누락·초과 키·음수·소수·과소 재료 저장은 거절한다.
4. 현재 저장 키와 writer lock을 유지한다. 저장 키를 새로 만들어 기존 기록을 분리하지 않는다. 현재 v6 앱은 v7 저장을 미래 버전으로 차단하므로 옛 탭이 새 저장을 덮어쓰지 않는지 실제 검증한다.
5. 주 저장뿐 아니라 백업·손상 주 저장에서 복구·업그레이드 저장 실패·둘째 탭 읽기 전용을 검증한다. 현재 `commitSave`는 backup을 쓴 뒤 main 실패가 날 수 있으므로 실패 후 baseline의 backupRaw를 반영하는 기존 재시도 계약을 유지한다. 옛 앱으로의 코드 롤백이 새 저장을 다시 쓸 수 있다는 가정은 하지 않는다.

## 화면과 표현의 합격 조건

- 채소를 수확한 뒤 쓰임이 한 문장으로 연결되고, 카페에 준비할 재료가 없는 경우 ‘토마토 1개가 필요해요 · 가방 0개’처럼 원인과 필요한 양이 표시된다. 현재 계절의 작물을 자동으로 강제 선택하지 않는다.
- 주문 패널은 ‘음료 / 수확 한 그릇’ → 기존 선택기 하나 → ‘토마토 1개 사용 · 가방 2개’ → 준비하기 → 받기의 순서다. 재료가 부족한 그릇도 선택해 이름과 필요량을 읽을 수 있고 준비 버튼만 비활성화한다. 받기 뒤에는 ‘2층 빈 의자에 앉아 음식주머니를 열어요’를 안내하며 자동 착석이나 친구 초대는 하지 않는다.
- 원재료 선택·준비·받기는 기존 패널 안에서 끝낸다. 세 채소 각각의 별도 메뉴나 장황한 제작 설명을 만들지 않는다. 이미 가진 음식은 직접 먹거나 건넬 수 있으며 새로 준비하도록 유도하지 않는다.
- 그릇 세 종류의 선택은 주문 위치에서만 제공한다. 앉은 뒤에는 현재 보유 음식 목록만 보여 준다. 기존 폰 세로 화면에서 친구 선택을 펼치면 패널이 두 인물과 탁자를 가리는 문제가 있으므로, 실제 먹기뿐 아니라 친구 전달 연출 중에도 두 줄 상태 중심으로 접는다. 명확한 중단·일어서기 접근은 유지하고, 연출이 끝나면 같은 선택을 복원한다. 친구 초대는 접힌 선택 영역에 두어 혼자 먹기보다 먼저 나오지 않게 한다.
- 작은 화면에서도 닫기·취소·일어서기·받기에 접근할 수 있다. 새 패널의 터치 목표는 최소 48px, 설명 본문은 최소 15px로 두고 선택 값과 수량은 색 외 글자로 구분한다. 움직임 줄이기에서는 음식이 공중에서 순간 이동해 보이지 않는 짧은 변화로 처리한다.
- 도름이와 친구의 손·한 입·입의 접촉, 그릇의 탁자 높이, 줄어든 내용물이 실제 3D에서 맞아야 한다. 커다란 그릇 전체를 얼굴로 들어 올리는 임시 표현은 통과시키지 않는다.
- 그릇은 낮고 둥근 크림색(`#F4E8D3`) 형태를 공유한다. 토마토는 살구분홍 바탕과 둥근 조각, 호박은 버터노랑 바탕과 각진 주황 조각, 잎채소는 연한 세이지 바탕과 길쭉한 잎으로 구별한다. 이름도 함께 표시한다. 코알라가 내려놓고 고개를 한 번 들거나 가는 김이 1~2줄 오르는 정도로 반응을 제한하며 계속 반짝이는 보상 효과를 추가하지 않는다.
- ‘익힌 채소’라는 설명은 준비 소품에서 조리된 상태를 확인할 수 있을 때만 쓴다. 이번 연출은 짧은 가상 준비·담기이며 실제 조리법 전체를 재현하거나 3초 만에 배웠다고 설명하지 않는다. 실제로 보이지 않는 가열이나 재료 변화를 학습 문구에서 완료했다고 말하지 않는다.
- 친구가 준비 중이거나 가게 손님으로 점유되어 초대할 수 없을 때도 혼자 먹기는 가능하다. 초대는 선택 사항이며 친구 도착·착석·귀가·중간 취소를 기존 동선과 함께 유지한다.
- 음식 보관에 유통기한이나 패널티를 추가하지 않는다. 모든 재료가 다 떨어져도 기존 무료 음료와 휴식은 그대로 사용 가능하다.

## 구현 순서와 검증 범위

**1. 저장 계약부터 완성.** 카탈로그·schema 7·버전별 검증·제작/식사 reducer를 한 묶음으로 작성한다. 세 채소마다 수확 → 준비 두 번 → 혼자 먹기/전달 각각 한 번 → 재수확의 반복 계산을 모델로 확인한다. 이 단계에서는 화면에 새 선택지를 노출하지 않는다.

**2. 한 재료의 실제 완주를 먼저 연결.** 토마토를 대표로 기존 카페 준비·받기·식사·친구 전달까지 구현한다. 새 그릇과 손 접촉이 실제 게임에서 자연스럽게 보이는지 검토한다. UI 문구·단위·준비 실패/소비 실패를 함께 확인한다. 컵으로 보이는 임시 구현을 완료로 표시하지 않는다.

**3. 나머지 두 재료와 작은 발견.** 같은 모형·그릇·동작을 사용하고 내용물·색·이름·짧은 관찰 문구만 변주한다. 세 재료 모두 실제 존재하는 사용처와 부족 안내를 확인한다. 기존 빵·음료의 표시와 식사도 대조한다.

**4. 통합 회귀와 실제 플레이 판정.** 다음 근거를 나눠 기록한다.

| 검사 | 최소 대상 |
| --- | --- |
| 저장·모델 | v5/v6 정상 업그레이드, v7 누락/초과 키 거절, v6에 새 키 위장 거절, v1~v4 호환, 3종 수량, 부족·상한·중복 받기·동시 소비·오래된 revision, 기존 음료와 장식 비용 유지 |
| 저장 실패·복구 | main/backup 실패와 재시도, 새로고침, 미래 버전 차단, 두 탭 writer/read-only, 사진·편지·기존 가방 보존 |
| UI 제어 | 원재료 선택 유지, 준비 중 변경 방지, 취소, 준비/소비 실패 뒤 문구, 반복 받기 방지, `pagehide`·재입장·좌석 해제·친구 귀가 |
| 실제 3D 입력 | 각 채소 실제 수확 → 카페에서 준비·받기 → 먹기, 대표 재료 2그릇 중 친구 전달 1+본인 식사 1, 같은 재료 두 번째 반복, 실제 가방 변화와 reload 일치 |
| 실제 화면 | 폰 세로·가로·태블릿·PC의 선택/닫기/일어서기, 준비 소품·손과 입 접촉·내용물 변화·친구 좌석·카메라, 움직임 줄이기 |

자동 모형으로 수량을 준비한 결과와 실제로 수확·받기·먹기를 조작한 결과를 구분한다. 테스트용 성공·시간·점수 주입을 실제 완주 증거로 쓰지 않는다. 저장 검토 담당자와 독립 시각·사용성 담당자의 지적을 반영한 뒤 새 출시 후보로 묶는다.

## 독립 저장 모델 검토와 남는 범위

저장 모델 담당자와 소스를 독립 대조한 결과, 채소별 고정 variant와 공통 UI가 원재료 추적용 중복 장부보다 작은 구조라는 의견에 합의했다. 옛 버전을 새 목록으로 검증하면 정상 저장이 깨지는 점, 받기에서만 원료를 차감해야 하는 점, 먹기/나눔의 접촉 시 단 한 번만 소비해야 하는 점, 출시 후 비용을 소급 변경하면 안 되는 점을 위 계약에 반영했다. 카페와 친구가 현재 컵 전용이라는 별도 지적도 소품·접촉·문구 합격 조건에 포함했다. 상세 근거는 [독립 저장·소비 계약 검토](../qa/harvest-use-contract-review-2026-11-06.md)를 따른다.

디자인 담당자는 기존 세로폰 친구 착석 캡처에서 펼친 패널이 도름이와 탁자를 가리는 점을 지적했다. 새 채소 선택은 주문 문맥에만 두고, 착석 후에는 보유 음식만 표시하며 친구 전달 때도 패널을 접는 안을 반영했다. 또한 손 접촉과 입 접촉을 혼용한 초안을 지적하여 실제 첫 한 입에서 소비하는 계약으로 통일하고, 작은 발견을 읽기 위한 새 단계를 만들지 않도록 조정했다. 이는 설계 검토이며 아직 새 구현의 안전성이나 시각 품질을 검증한 결과는 아니다.

이번 주기는 채소 세 종류의 반복 쓰임만 맡는다. 꽃잎의 반복 쓰임, 집 요리의 실제 재료 연결, 친구별 긴 대화, 식사 도감, 대량 제작은 이후 사용 관찰에 따라 판단한다. 새 결제·백엔드·마감·출석 과제는 추가하지 않는다.
