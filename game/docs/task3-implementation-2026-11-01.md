# 놀이섬 출시 검토와 개선 — 2026-11-01

이번 검토는 실제 목표, 조작 결과, 완료·재도전·퇴장까지 이어지는지를 기준으로 한다. 기존 QA를 새 증거로 사용하지 않았다. 브라우저 검수는 별도 테스트 컨텍스트와 `game.js` 응답에만 삽입하는 탐색 fixture를 사용하며, 실제 플레이는 키보드·화면 버튼·터치 입력으로 한다. 사용자 저장과 원본 모델은 건드리지 않는다.

## 수정 전 확인

- 인형뽑기: 실제 방향키로 집게를 움직여 빗나감 → 다시 → 곰 인형 성공 → 나가기까지 확인했다. 짧은 조준 장난감으로 성립한다. 수집 경쟁이나 보상을 억지로 붙이지 않았다.
- 뜰채: 중앙에서 움직이지 않고 버튼만 누른 새 브라우저 판이 **69회 중 63회 성공(91.3%)**했다. 모델 세 시드도 84회 중 76–77회 성공했다. 조준을 요구하는 안내와 실제 플레이가 어긋났다.
- 간식: 아이스크림·슬러시·핫도그·츄러스 각각 선택 → 받기 → 먹기 → 마무리를 확인했다. 무료 간식을 들고 쉬는 역할놀이로 평가한다.
- 카트: 모델에서 16.225초 완주 후 재도전을 준비하려면 퇴장 10.808초 + 재탑승·카운트다운 8.7초가 추가됐다. 결과에서 다시 시작할 수 없었다.
- 범퍼카: 첫 전진은 앞 벽을 향해 0.35m 이동하고 멈췄다. 경주로 잘못 홍보하지는 않았지만, 조작 피드백과 선택 활동이 부족했다.
- 카트·범퍼카: 새 브라우저에서 3D가 빈 하늘로 축소되고, 퇴장 버튼은 이동 스틱에 가려 클릭하지 못했다. `bumperSafeArea`가 오른쪽 위 안내를 하단 패널로 계산해 사용 가능한 높이를 거의 0으로 만든 것이 카메라 원인이다. 공통 조작 배치는 root가 별도로 수정했다.
- 구현 후 전체 흐름에서 작은 코스터에도 같은 안전 영역 계산 오류가 남아 있는 것을 발견했다. 상단 안내를 하단으로 예약하지 않도록 코스터 카메라도 별도로 회귀를 추가해 수정했다.
- 회전목마·바이킹·작은 코스터는 휴식 탑승이다. 점수나 실패를 추가하는 대신 풍경, 조작 안내, 명시적 종료를 검증한다.

## 구현

### 뜰채

- 기본은 **느긋한 연습**이다. 시간 제한 없이 네 빛깔 물고기를 만나고, 스스로 이번 놀이를 마칠 수 있다. **50초 도전**은 사용자가 선택한다.
- 네 물고기의 궤도를 연못 안에서 분산하고 실제 잡기 반경을 .34에서 .23으로 맞췄다. 중앙 연타로 성공하는 문제를 없애고, 일반 스틱 이동으로 네 종류 모두에 닿을 수 있음을 검증한다.
- 뜰채 아래 수면에 실제 판정 반경을 표시한다. 원 안에 들어오면 색과 문장으로 함께 알려 준다. 성공에는 물고기의 빛깔을, 빗나감에는 다음 조작 방법을 안내한다.
- 네 빛깔 기록, 시도·성공 결과, 이번 방문 최고 기록, 즉시 다시하기를 제공한다. 물고기는 다시 연못으로 돌아오며 새 저장 스키마나 재화는 추가하지 않았다.
- 연못 밖에서 네 물고기가 겹쳐 있거나 잡힌 채 숨는 상태를 정리했다. 물고기가 실제로 헤엄치는 방향을 바라보게 수정했다. 수면 원·작은 잎·크림/민트 패널은 기존 파스텔 미감과 작은 기하 예산을 유지한다.
- 잡기마다 누르고 있던 방향키·터치 스틱이 끊기던 문제도 독립 검토에서 재현해 수정했다. 잡는 동안만 멈추고 이후 자연스럽게 이어지며, 일시정지·종료에서는 입력을 초기화한다.
- 작은 화면의 안내 글자·버튼을 키우고, 놀이 중 산책용 안내를 가렸다. 이동 스틱의 설명을 뜰채 조작으로 바꾸고 종료 때 원래대로 돌려놓는다.
- 375×667 화면에서 아래 조작이 연못을 덮는 문제를 새 캡처로 확인해 두 열 버튼과 짧은 터치 안내로 정리했다. 첫 손가락으로 스틱을 민 채 두 번째 손가락으로 뜰채를 내릴 수 있으며, 한 번의 터치가 중복 실행되지 않는다.

### 카트·범퍼카

- 카트의 실제 탑승은 **느린 자유 연습 + 길 따라가기 도움**으로 시작한다. 1랩 기록 도전은 선택하며, 도움은 켜거나 끌 수 있다.
- 카트 결과에 직전·최고 기록과 **한 번 더 출발**을 제공한다. 내렸다 다시 탑승하지 않고 카운트다운부터 이어 간다.
- 범퍼카는 탑승 후 안쪽으로 방향을 돌려 첫 전진이 막히지 않게 한다. 선택형 길표시 세 곳 찾기, 도착 결과, 바로 다시하기, 쿠션 접촉 반응을 추가했다. 시간 제한 없는 자유 운전도 유지한다.
- 두 운전의 카메라는 상단 안내와 하단 조작을 구분하고 최소 장면 면적을 확보한다. 새 조작 패널도 화면 안전 영역에 포함한다.
- 공통 `index.html`의 `amusement/bumper-play.css` 연결과 스틱/퇴장 버튼 겹침은 root 통합 변경에 속한다.

### 휴식 탑승의 시야

- 작은 코스터의 카메라 안전 영역을 수정하고, 1440×900·390×844·320×568·667×375 및 오프셋이 있는 화면에서 조작 영역과 캐릭터 크기를 검증했다. 같은 안내 좌표 계산 패턴을 검색해 범퍼카와 코스터 이외에는 없음을 확인했다.
- 회전목마는 정상 렌더로 여러 반투명 성벽이 도름이 앞에 겹치는 것을 먼저 확인했다. 앉아 있는 동안 실제로 시야를 가리는 앞쪽 면만 완전히 투명하게 하며, 걷기·내리기·전체 보기에서는 기존 투명도와 외관을 복원한다. 원본 모델의 배 소용돌이와 모델 배율은 바꾸지 않았다.
- 최종 정상 렌더 `carousel-normal-final/carousel-visual-clear-foreground.png`에서 얼굴·몸이 선명하게 보인다. 별도 독립 코드 검토도 해당 변경의 범위에서 P0/P1 없이 통과했다.

`scripts/amusement-review-2026-11-01.mjs`와 `scripts/amusement-release-scenarios-2026-11-01.mjs`가 재현 스크립트다. 이동을 위한 장면 탐색 fixture는 브라우저 응답에만 삽입한다. 모델·tick·물리·입력·시간은 제품 구현 그대로다. 네 물고기의 위치, 차의 방향과 결과를 읽어 일반 키보드·터치 입력을 선택하며 성공 상태를 주입하지 않는다.

입력 범위: 뜰채의 네 빛깔은 방향키 조준과 잡기 버튼으로 완성하며, 휴대폰·태블릿에서는 별도로 실제 두 손가락(스틱 유지 + 잡기)을 검증한다. 카트는 데스크톱·휴대폰에서 방향키, 태블릿에서 실제 터치 스틱으로 연습과 완주를 확인한다. 범퍼카 세 표식 경로는 세 화면 모두 방향키로 진행하며, 터치 스틱의 전달과 카메라 독립성은 호스트 회귀에서 확인한다. 모든 재도전과 퇴장은 실제 화면 버튼을 클릭한다.

소프트웨어 렌더러에서 긴 완료 흐름을 확인하기 위해 일부 실행은 그리기만 12프레임마다 한다(`rendererStride: 12`). 캡처 때는 일반 렌더와 clear를 함께 복원한다. 최초 `flow-desktop` 샘플러는 clear와 일치하지 않아 **뜰채 흰 이미지가 시각 근거로 부적합**하므로 이후 수정된 휴대폰·태블릿 캡처로 대체한다. `flow-desktop`의 코스터 초기 시야 역시 수정 전이므로 최종 화면으로 주장하지 않는다. 정상 렌더 회전목마 캡처는 `rendererStride: 1`이다. 기기의 실제 FPS나 네트워크 성능을 검증한 것으로 해석하지 않는다.

수정 후 뜰채는 조준의 이유와 결과가 생겼고, 카트·범퍼카는 처음 조작부터 목표·마무리·재도전까지 이어진다. 휴식 탑승은 점수 없이 감상하다 원할 때 나갈 수 있는 활동으로 유지한다. 시판 레이싱 게임이나 다단계 미니게임의 콘텐츠 양에 도달했다는 평가는 하지 않는다.

이 담당 범위에서 확인한 출시 차단 P0/P1은 모두 해소했다. 정상 렌더와 세 화면 크기 검토, 32개 집중 회귀, 별도 독립 코드 검토를 마쳤고 제품 코드 변경을 종료한다. 전체 앱의 최종 합격·GitHub·배포는 root의 통합 검토에 따른다.


## 남은 확장 여지

간식 네 종류는 정상적으로 먹을 수 있지만, 넓은 마을 카메라에서는 작은 소품과 먹는 동작이 작게 보인다. 간식 전용 가까운 시점은 비차단 후속 개선으로 남긴다. 이번 수정은 카트·범퍼카·뜰채의 실제 조작 및 완료 흐름을 우선 완결한다.

상단의 첫 안내를 펼쳐 둔 태블릿 카트 화면에서는 안내와 캐릭터 머리 일부가 겹칠 수 있다. 안내 접기 버튼으로 해소되며 운전 입력·결과·퇴장을 가리지는 않는다. 놀이 방식 선택은 첫 주행에 자동으로 접힌다. 공통 안내의 추가 자동 접기는 후속 편의 개선 범위다.
